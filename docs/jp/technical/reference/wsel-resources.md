# WSELのリソース

[日本語一覧](../../README.md) | [抽出ツール](../../../../tools/data/overlays/README.md) | [English](../../../en/technical/reference/wsel-resources.md)

WSELは「プレイエリアを選択してください。」の画面です。
最初はワールドマップの前に主人公が立っている画面で、決定を押すとマップへズームし、
もう一度決定を押すまで案内の画像を表示します。そのあと羊皮紙の土地マップが現れ、
96ピクセル四方の枠を19 x 19のグリッド上で動かしてセルを選びます。
暗いセルを選ぶとエラー音が鳴って選べません。
もう一度決定するとセル番号をセーブデータの`world_map_cell`に書き込み、オーバーレイを終了します。

画面に表示するものは、オーバーレイに埋め込まれた8枚のTIM画像といくつかの小さな表で全部です。
両バージョンのYAMLでは、これらを1つの`wsel_data` databinにまとめています。
ビルドでは元のバイト列をそのままリンクし、別の抽出ツールで中身を見られるようにします。

```sh
make splat
make extract-wsel

make splat VERSION=jp
make extract-wsel VERSION=jp
```

出力先は`assets/exports/<version>/overlays/wsel/`です。
`WSEL_OUTPUT=/path/to/new-folder`で別の場所を指定できます。
既存のフォルダは上書きしません。すべて読み終えてから一時フォルダに書き込み、
完了した時点で出力先へ移動します。書き込みに失敗した場合は一時フォルダを削除します。

## 出力されるもの

| パス | 内容 |
| --- | --- |
| `byte-map.yaml` | TIM末尾の繰り返しワード、パディング、画面の状態を含む、blob内の全範囲 |
| `images/<layer>/image.tim` | スプライトレイヤーごとの元のTIM |
| `images/<layer>/image.yaml` | 格納時のTIM配置、対応するスプライトレイヤー、ゲームが転送するVRAM座標 |
| `images/<layer>/palette_00.png` | パレットを通して表示した画像全体 |
| `images/hero_default/poses/`、`images/hero_alternate/poses/` | 各主人公シートの12個のポーズを切り出した画像 |
| `tables/sprite_layers.yaml` | 8件のスプライトレイヤーレコード |
| `tables/hero_poses_default.yaml`、`tables/hero_poses_alternate.yaml` | 各主人公シートの12件のポーズレコード |
| `tables/cell_occupied.yaml` | グリッドのセルごとのフラグ。0以外のセルは選べません |
| `tables/cell_tile_masks.yaml` | 361個のセルそれぞれに対する6 x 6のタイルマスク |

どの表も、デコードした値の横に元のバイト列を残しています。
USとJPの違いは案内の画像だけで、英語か日本語かが異なります。

## 画像

`wsel_load_resources`は、n番目のTIMをn番目のスプライトレイヤーへ転送します。
出力のレイヤー名は、`wsel.c`の`WSEL_SPRITE_*`の定義から取っています。

| フォルダ | サイズ | 色数 | 内容 |
| --- | --- | --- | --- |
| `land_map` | 416 x 416 | 8ビット | 枠を動かす羊皮紙の土地マップ |
| `world_map` | 320 x 224 | 8ビット | 額縁付きのワールドマップと石の背景 |
| `cursor` | 120 x 118 | 4ビット | 96ピクセル四方の枠を囲む黄色いフレーム |
| `world_overlay` | 320 x 224 | 4ビット | ワールドマップの上に減算で重ねる暗いビネット |
| `hero_default` | 256 x 256 | 8ビット | 片方の主人公のポーズシート |
| `hero_alternate` | 256 x 256 | 8ビット | もう片方の主人公のポーズシート |
| `hero_shadow` | 256 x 256 | 4ビット | 主人公の足元に描く32 x 10の影を含む画像 |
| `prompt` | 184 x 88 | 4ビット | 「プレイエリアを選択してください。(枠内が暗く表示されたエリアは選べません。)」 |

どのTIMもパレットは1つです。プレビューでは値0を透明、それ以外を不透明として表示します。
ゲーム中の半透明処理や明るさは反映しないので、ビネットはただの暗い画像に見えます。

ゲームは各TIMに格納されたVRAM座標を使いません。
`wsel_upload_tim`はレイヤーレコードの値を使い、ピクセルをレイヤーの`tpage_x`/`tpage_y`へ、
パレットを`clut_x`/`clut_y`へ1行として転送します。
`image.yaml`には両方を`stored_layout`と`uploaded_to`として載せています。
画像を差し替える場合、転送先を決めるのはレイヤーレコードの方です。

各TIMの後ろには、最後の4バイトのコピーが続きます。
このワードはバイトマップに記録していますが、出力するTIMには含めません。

## スプライトレイヤーと主人公のポーズ

レイヤーレコードは24バイトです。先頭に`tpage_mode`(0が4ビット、1が8ビット)、
`blend_mode`、`semi_trans`、`brightness`の4バイトが並び、そのあとに16ビット値が10個続きます。
テクスチャページのXとY、パレットのXとY、元画像のUとV、幅、高さ、画面上のXとYです。
明るさ128が標準です。描画処理はレイヤーを最大128 x 256ピクセルの短冊に分け、
それぞれを1つのテクスチャページとして描きます。
レイヤー2(カーソル)には、右下に2ピクセルずらした黒い影も付きます。

画面の実行中に変わるフィールドもあります。
レイヤー0と2は明るさと半透明の設定を段階的に変えてフェードインし、
スクロールとカーソルに合わせて位置も動きます。格納されている値は初期状態です。

レイヤー4から6は普通のスプライトとしては描かないので、幅と高さは0です。
代わりに`wsel_draw_hero`が主人公を描きます。
セーブデータの`0x800435E0`(US)または`0x80043748`(JP)にある1バイトの下位7ビットが0なら
default側、それ以外ならalternate側のシートを使います。
ポーズレコードは6バイトで、すべて8ピクセル単位です。U、V、幅、高さ、Xオフセット、Yオフセットの順です。
ポーズの左上は、レイヤーのX + 32 - Xオフセット x 8、Y + 40 - Yオフセット x 8に置かれます。
格納されているレイヤー位置(216, 180)の場合、ポーズ0は32 x 48のセルとして(216, 172)に描かれます。
影は影シートの(184, 6)にある固定のセルで、レイヤーのX、Y + 32に描きます。

実際に描かれるのは、立ちポーズのポーズ0だけです。残りの11個は、それぞれ武器を持ったポーズです。

## 土地マップのグリッド

土地マップは一辺が16ピクセルのセル26個分です。カーソルの枠は6 x 6セルを覆い、
枠の左上は外周から1セル内側を起点とする19 x 19のどのセルにも置けます。
カーソル下のセルは各軸で`(cursor - scroll - 16) / 16`、
選んだセルは`column + row x 19`として保存されます。

`cell_occupied`はセルごとに1バイトを行順に並べたもので、後ろに3バイトの0のパディングが続きます。
0以外のセルは全体が暗く表示され、選ぶとエラー音が鳴ります。
出力には`0`と`1`の19本の文字列としてもグリッドを書き出すので、マップの絵のように読めます。

`cell_tile_masks`はセルごとに36バイトで、そのセルから始まる枠の6 x 6マスクです。
空いているセルで□ボタンを押している間、値が0のタイルを明るく表示します。
さらに枠の外側にもう1行と1列を描きます。これは下のセルの最終行と、右のセルの最終列から取ります。

## 実行時の状態とバイトマップ

データblobは両バージョンとも492,252バイトです。最後の16,500バイトはディスク上ではすべて0です。
描画バッファのポインター、曲のシーケンスを受け取るバッファ、
フェード、入力、スクロール、カーソルの変数がここに入ります。
バイトマップにはこの範囲を記録しますが、別のファイルは書き出しません。
それ以外のバイトはすべて、リソース、TIMの繰り返しワード、3バイトのパディングのどれかに当たるので、
どちらのバージョンでも`unknown/`フォルダは作られません。
判別できない0以外のデータがあれば、そのままそこに保存されます。

[`wsel.py`](../../../../tools/data/overlays/wsel.py)は、ほかのオーバーレイ抽出ツールと同じく
リーダー、`Part`、ライターの構成になっています。出力したファイルを編集しても、ビルドでリンクされる内容は変わりません。
