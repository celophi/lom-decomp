# NIKIのリソース

[日本語一覧](../../README.md) | [抽出ツール](../../../../tools/data/overlays/README.md) | [English](../../../en/technical/reference/niki-resources.md)

NIKIは日記の画面です。FIELDが`field_open_niki`で開き、どちらのメモリーカードの
セーブも扱えます。モード0では、カード内のセーブを一覧にして、選んだセーブの詳細を
表示し、ロードします。もう1つのモードでは一覧を出さずに1つのセーブだけを扱います。
セーブを読み戻し、メモリ上の256バイトのブロックをそこへコピーしてから書き直します。

NIKIの初期化済みデータは、両地域のYAMLとも1つの`niki_data` databinに入っています。
中身はADDHEROと同じカード画面用のリソースで、メッセージ、メモリーカードの
タイトル雛形2つ、場所名、パーティーアイコン、カード処理シーケンス、文字表、
数字グリフです。ビルドはこのblobをそのままリンクします。中身を見るには、
まずsplatで素材を抽出してから、次のコマンドを実行します。

```sh
make splat
make extract-niki

make splat VERSION=jp
make extract-niki VERSION=jp
```

出力先は`assets/exports/<version>/overlays/niki/`です。
`NIKI_OUTPUT=/path/to/new-folder`で別の場所を指定できます。出力先は新しい
フォルダである必要があります。抽出ツールはすべてを読み終えてから一時フォルダに
書き込み、完成したところで所定の場所へ移動します。途中で失敗しても何も残りません。
出力を編集しても、ビルドがリンクする内容は変わりません。

## 出力されるもの

| パス | 内容 |
| --- | --- |
| `byte-map.yaml` | パディング、アイコンの繰り返しワード、変数も含む、blobの全範囲 |
| `text/messages.yaml` | 北米版91件、日本版90件のメッセージ。番号、シンボル名、元のバイト列付き |
| `text/card_titles.yaml` | Shift-JISのメモリーカードタイトル雛形2つと、それぞれの用途 |
| `text/locations.yaml` | セーブに記録された曲番号で選ぶ63件の場所名 |
| `icons/icons.yaml` | アイコン番号、キャラクターの種類、オフセット、保存されているパレット |
| `icons/icon_00.png` ... | 48 x 48のパーティーアイコン86個 |
| `tables/card_steps.yaml` | 8つのメモリーカード処理シーケンス。処理名は`CardMenuStep`と`CardMenuExchangeStep`(card_menu.h)から取得 |
| `tables/text_conversion.yaml` | 文字表。各テキストコードがShift-JISの何になるか |
| `tables/digit_glyphs.yaml` | 10進数と16進数に使う全角数字 |

どちらのバージョンにも`unknown/`フォルダはありません。blobのすべてのバイトが、
デコードしたリソース、ゼロのパディング、変数のいずれかに当たります。今後の変更で
未解釈の範囲にゼロ以外のバイトが出てきた場合は、アドレス名で`unknown/`に保存します。

## blobの配置

アドレスはオーバーレイが動作するRAM上のアドレスです。blobのサイズは北米版が
158,088バイト、日本版が161,652バイトです。

| 範囲 | 北米版 | 日本版 | シンボル |
| --- | --- | --- | --- |
| メッセージ | `0x801470F8`、0x499バイト | `0x801470E4`、0x5E1バイト | `g_niki_text_table` |
| カードタイトル雛形 | `0x80147594`、0x15バイト x 2 | `0x801476C8`、0x15バイト x 2 | なし |
| 場所名 | `0x801475C4`、0x1E0バイト | `0x801476F8`、0x175バイト | `g_niki_location_names` |
| パーティーアイコン | `0x801477A8`、0x18F1Cバイト | `0x80147870`、0x18F1Cバイト | `g_niki_icon_offsets`は4バイト後ろ |
| カード処理 | `0x801606C8`、0x34バイト | `0x80160790`、0x34バイト | `g_niki_card_setup_sequence` |
| 文字表 | `0x801606FC`、0x338バイト | `0x801607C4`、0x1044バイト | `g_glyph_single_byte_chart` |
| 数字グリフ | `0x80160A34`、0x3Cバイト | `0x80161808`、0x40バイト | `g_glyph_decimal_digits` |
| 変数 | `0x80160A70`、0xD010バイト | `0x80161848`、0xD010バイト | `g_niki_dialog_state` |

この間には、北米版で13バイト、日本版で12バイトのゼロのパディングがあります。
ほかに、アイコンセットの直後に、最後のワードを繰り返す4バイトがあります。

## テキスト

どちらのテキストテーブルも、オーバーレイでよく使う形式です。テーブル先頭からの
u16オフセットの一覧のあとに、ゼロ終端の文字列が続きます。コードについては
[テキストテーブル](text-tables.md)のページを参照してください。北米版はASCIIで表示し、
辞書の断片や制御コードは`{16}`("in")のように波括弧で書きます。日本版はNIKI自身の
文字表でデコードするので、ほかのオーバーレイは必要ありません。どのエントリにも
テキストの横に元のバイト列を残します。

メッセージテーブルはADDHERO、CARDA、CLOADにあるもののコピーなので、NIKIが
表示しないテキストも含まれます。NIKIが描画するのは30件ほどです。それらには
オフセット表の位置を指す`g_niki_text_*`シンボルがあり、出力ではエントリの横に
その名前を付けます。たとえばエントリ34には`g_niki_text_select_save_data`が付きます。
「はい/いいえ」の選択肢の文字はこのテーブルではなく、FIELDのものです。

エントリ29と33は北米版では空です。日本版ではそれぞれ「リング・りんぐ・ランド」と
「ポケットステーションではありません」が入っています。NIKIはエントリ29を
リング・りんぐ・ランドのファイルの一覧ラベルに使うので、北米版ではその行に
ラベルが出ません。エントリ33はステータスダイアログ3で使われ、このダイアログは
`CARD_MENU_STEP_CHECK_POCKETSTATION`が失敗したときにだけ開きます。

カードタイトル雛形は、メモリーカードのセーブに使うShift-JISのタイトル2つです。
NIKIはセーブにもともと付いているタイトルをそのまま残し、これらは書き込みません。
CARDAが使うもののコピーを持っているだけです。

## アイコン

アイコンセットは、個数(86)と、その個数ワードから数えたバイトオフセットの一覧で
始まります。各アイコンは16色のパレットと、48 x 48の4ビット画像(下位ニブルが先)です。
NIKIは選んだセーブのパーティー分のパレットとピクセルを転送します。PNGは保存されている
パレットを使い、色0を透明にしています。ゲストの主人公とゴーレムは、ゲームが実行時に
作るパレットで描かれるので、ここでは正しい色になりません。

## カード処理シーケンス

カード処理シーケンスは1バイトのコマンドの並びで、`CARD_MENU_STEP_DONE`(0)まで
順に実行されます。出力では、テーブル内のすべてのシンボルから停止バイトまでをたどり、
各コマンドにADDHERO、CARDA、CLOADと共有する`include/common/card_menu.h`の
`CardMenuStep`と`CardMenuExchangeStep`から名前を付けます。
`g_card_steps_idle`には処理のない`CARD_MENU_STEP_WAIT`(14)が入っているので、
メニューが別のシーケンスを選ぶまでそこで待ち続けます。

テーブルには一度も実行されないバイトが1つあります。`g_niki_write_save_sequence`の
直前のバイト(北米版`0x801606F4`、日本版`0x801607BC`)は
`CARD_MENU_STEP_CLEAR_SOFTWARE_EVENTS`ですが、コードは書き込みシーケンスをその次のバイトから
始めます。出力では`unreached`に記載し、テーブル全体も`bytes`に残します。

## 文字表、数字、変数

文字表は33バイトの行でできています。2バイトのShift-JIS文字16個と改行です。
0x20以降の1バイトコードは最初の数行を指します。リードバイト0x19から0x1Fは、
`g_glyph_chart_page_base`から数えた16行のページを選びます。このシンボルは
ページ0があるはずの位置で、0x19より前のページは存在しないため、アイコンセットの
中を指しています。日本版の文字表には7ページすべてがあります。北米版は824バイトしかなく、
1バイトコードの行とページ0x19の大部分だけです。出力には文字表の範囲に入る行だけを
載せ、保存されている行もそのまま残します。NIKIにはこの文字表を読む変換処理が
含まれていますが、呼ばれることはありません。抽出ツールは日本版のテキストの
デコードにこの文字表を使います。

数字グリフは全角の`0`から`9`、続いて`0`から`F`で、それぞれゼロ2バイトで終わります。

最後の53,264バイトはNIKIの変数とバッファです。ダイアログの状態、セーブの転送用
バッファ、カードのディレクトリエントリ、グリフキャッシュが並び、`g_glyph_cursor_y`で
終わります。ディスク上ではすべてゼロです。この範囲はバイトマップに記録し、
別のファイルにはしません。

`bu00:`のデバイス名、`bu00:*`の検索パス、全角の`ＭＡＸ`はこのblobにはありません。
パスは[`niki.c`](../../../../src/overlays/niki/niki.c)と
[`niki_io.c`](../../../../src/overlays/niki/niki_io.c)で定義されています。
`ＭＡＸ`は共有の[`format_decimal.inc.c`](../../../../src/common/sjis/format_decimal.inc.c)にある文字列です。

文字表とアイコンのサイズが`niki_internal.h`の`#define`や構造体と一致することを確認します。
