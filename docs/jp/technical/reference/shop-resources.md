# SHOPのリソース

[日本語一覧](../../README.md) | [抽出ツール](../../../../tools/overlays/README.md) | [English](../../../en/technical/reference/shop-resources.md)

SHOPは、フィールドの店で開く売買画面です。持っているデータは多くありません。
アイテム一覧と詳細ウィンドウのテキスト、アイテムの種類ごとの売値、店の変数だけです。
両バージョンのYAMLでは、これらを1つの`shop_data` databinにまとめています。
ビルドでは元のバイト列をそのままリンクし、別の抽出ツールで中身を見られるようにします。

```sh
make splat
make extract-shop

make splat VERSION=jp
make extract-shop VERSION=jp
```

出力先は`assets/exports/<version>/overlays/shop/`です。
`SHOP_OUTPUT=/path/to/new-folder`で別の場所を指定できます。
既存のフォルダは上書きしません。すべて読み終えてから一時フォルダに書き込み、
完了した時点で出力先へ移動します。書き込みに失敗した場合は一時フォルダを削除します。

## 出力されるもの

| パス | 内容 |
| --- | --- |
| `byte-map.yaml` | パディングと店の変数を含む、blob内の全範囲 |
| `text/archive.bin` | 元のテキストアーカイブ全体 |
| `text/archive.yaml` | 4つのセクションのオフセットと、各セクションの出力ファイル |
| `text/item_descriptions.yaml` | アイテムの種類ごとの分類表示256件 |
| `text/item_names.yaml` | アイテムの種類ごとの名前256件 |
| `text/equipment_types.yaml` | 武器、防具、楽器の種別名32件 |
| `text/instrument_spells.yaml` | 楽器の魔法名112件。8体の精霊ごとに14件 |
| `tables/sell_prices.yaml` | アイテムの種類ごとの売値と、その名前 |

テキストの各エントリには、番号、セクション内のオフセット、デコードした文字列、
元のバイト列が入ります。日本版のテキストは、同じバージョンのCLOADの文字表で
デコードします。`make splat VERSION=jp`でそのblobも抽出され、文字表の出所は
`byte-map.yaml`に記録されます。北米版の辞書コードや制御コードは、ほかの
オーバーレイの出力と同じく波括弧で表示します。セクションの最後の文字列の後にある
ゼロバイトは、そのセクションのYAMLに`padding`として記録します。

## 配置

SHOPは`0x80140000`に読み込まれます。アドレスから`0x80140000`を引くと、
展開後のSHOP.BIN内のオフセットになります。オーバーレイの展開方法は
[テキストテーブル](text-tables.md)のページにあります。

| 範囲 | USのアドレス | JPのアドレス | サイズ |
| --- | --- | --- | --- |
| テキストアーカイブ | `0x80142D04` | `0x80142CF8` | USは`0x22B0`、JPは`0x1E44` |
| 売値 | `0x80144FB4` | `0x80144B3C` | `0x200` |
| ゼロのパディング | `0x801451B4` | `0x80144D3C` | 4バイト |
| 店の変数 | `0x801451B8` | `0x80144D40` | `0xB2C` |

blob全体はUSが12,256バイト、JPが11,124バイトです。
最後の2,860バイトは、店の変数と一覧用のバッファです。
ディスク上ではすべてゼロなので、バイトマップに記録するだけで別のファイルにはしません。
それ以外のバイトはすべてアーカイブ、売値テーブル、その間のパディングのどれかに
当たるため、どちらの版も`unknown/`フォルダは不要です。

## テキストアーカイブ

アーカイブの先頭には20バイトのヘッダがあります。16ビットのセクション数(常に4)、
16ビットのゼロ、続いてアーカイブ先頭から数えた32ビットのオフセットが4つです。
各セクションは通常のテキストテーブルで、16ビットの文字列オフセットは
そのセクションの先頭から数えます。

| セクション | シンボル | 件数 | 店での使い道 |
| --- | --- | --- | --- |
| 0 | `SHOP_TEXT_ITEM_DESCRIPTIONS` | 256 | カーソルが通常のアイテムにあるときの詳細ウィンドウの見出し |
| 1 | `SHOP_TEXT_ITEM_NAMES` | 256 | 通常のアイテムの一覧表示と、装備名の素材部分 |
| 2 | `SHOP_TEXT_EQUIPMENT_TYPES` | 32 | 装備名の種別部分 |
| 3 | `SHOP_TEXT_INSTRUMENT_SPELLS` | 112 | 楽器の詳細ウィンドウに表示する魔法 |

セクション0と1は、所持数と同じアイテムの種類番号で引きます。
アイテム名の最初の64件は素材名も兼ねています。装備レコードは素材を6ビットで持ち、
店は素材名、FIELDのUI文字列にある区切り、種別名の順につないで装備名を作ります。
区切りは北米版では空白1文字なので、アイテム0を素材にした武器種別0は
北米版で「MenosBronze Knife」と表示されます。

装備の種別名は、3つの分類で1つの表を共有しています。武器は番号0から、
防具は11から、楽器は23から始まり、レコードの種別番号をその開始位置に足します。
USとJPのどちらも武器11種、防具12種、楽器4種で、27から31は空です。
出力では各エントリの横に分類と種別番号を書きます。

魔法のセクションは表になっています。楽器のレコードは精霊の番号と魔法の番号を持ち、
店は`精霊 * 14 + 魔法`番目のエントリを読みます。出力では両方の番号を名前の横に書きます。
北米版では各行の最後の魔法が精霊の名前で始まる(`Wisp{18}Blaze`、
`Shade{18}Scythe`など)ので、行を見分ける手がかりになります。

北米版のアイテム分類はバイナリエディタで見ると少し変わっています。
2列目の位置をそろえるために空白のコードを使っているからです。
`{08}`は空白2つ、`{09}`は3つ、`{0A}`は4つ、`{0B}`は次のバイトを個数として読みます。
つまり`METAL{08}Primary{0B}{0F}`は「METAL」、空白2つ、「Primary」、空白15個です。
これらのコードはFIELDのテキスト描画処理(`field_text.c`)で定義されています。

アーカイブを編集するときは、エントリの数を変えないでください。店は番号で文字列を探します。
売値テーブルはアーカイブの直後から始まるので、後ろのデータをすべて移動しない限り、
アーカイブを今のサイズより大きくはできません。文字列を長くした場合は、同じセクション内で
それより後ろの文字列オフセットを更新します。セクションが大きくなった場合は、
それより後ろのセクションオフセットも更新が必要です。

## 売値

売値テーブルは、アイテムの種類ごとに1つずつ並んだ256個のリトルエンディアン16ビット値です。
売るときには、SHOPはプレイヤーが持っているアイテムの種類を一覧にし、
それぞれにこの値段を付けます。一覧では選んだ個数を掛けて表示します。
装備レコードはこの表を使わず、レコードごとに自分の値段を持っています。

買値もここにはありません。店を開くフィールドのスクリプトが、並べる商品をSHOPに渡します。
その商品一覧の各エントリが自分の値段を持っています。

[`shop.py`](../../../../tools/overlays/shop.py)も、ほかの抽出ツールと同じく、
読み取り処理、`Part`、書き込み処理を分けています。セクション名は
`shop_internal.h`の`ShopTextSection`列挙型から取得します。
抽出結果を編集しても、ビルドがリンクするデータは変わりません。
