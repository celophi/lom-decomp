# GNAMEのリソース

[日本語一覧](../../README.md) | [抽出ツール](../../../../tools/overlays/README.md) | [English](../../../en/technical/reference/gname-resources.md)

GNAMEには、名前入力画面の画像、文字パネル、名前のリストが入っています。
以前のYAMLでは複数のアセット形式に分けていましたが、両バージョンとも
1つの`gname_data` databinにまとめました。中身を見るための抽出ツールは別に用意し、
ビルドでは元のバイト列をそのままリンクします。

```sh
make splat
make extract-gname

make splat VERSION=jp
make extract-gname VERSION=jp
```

出力先は`assets/exports/<version>/overlays/gname/`です。
`GNAME_OUTPUT=/path/to/new-folder`で別の場所を指定できます。
既存のフォルダは上書きしません。すべて読み終えてから書き込みを始め、
書き込みに失敗した場合は一時フォルダを削除します。

## 入っているもの

| パス | 内容 |
| --- | --- |
| `byte-map.yaml` | パディングやTIM末尾の繰り返しワードを含む、blob内の全範囲 |
| `image/image.tim` | 元の256 x 256、4ビットのテクスチャ |
| `image/image.yaml` | TIMの格納時の配置、パレット値、スプライト座標 |
| `image/palette_00.png`から`palette_0F.png` | 16パレットそれぞれで表示したテクスチャ全体 |
| `image/glyphs/00.png`から`38.png` | 各自のパレットで切り出した39枚のUIスプライト |
| `text/resource.bin` | 元の名前レコードアーカイブ全体 |
| `text/resource.yaml` | ヘッダと4つのテーブルのオフセット |
| `text/*.yaml` | 文字パネル、漢字、履歴用の名前、ランダム名。番号と元のバイト列付き |
| `tables/` | パネル境界、カテゴリ対応表、グリフ情報、タブカーソル、背景スプライト座標、文字追加アニメーション |

テクスチャ全体のプレビューは画像を探すのに便利ですが、ゲームはスプライトごとに
別のパレットを使います。切り出した画像には、そのスプライトのパレットを適用します。
影や色の変更など、実行時の画面合成までは再現せず、元の絵を見られるようにしています。

TIMには画像座標(0, 0)と、パレット座標(0, 480)が格納されています。
パレットは16 x 16の配置ですが、GNAMEは実際には256色を1行に並べて(0, 498)へ転送し、
画像は(320, 0)へ転送します。また、ゼロ以外の色にはSTPビットを立てます。
出力するTIMは格納時の値と座標を保ちます。PNGでは値ゼロを透明にし、
それ以外の色は不透明に表示します。

## 名前のテーブル

| テーブル | USの件数 | JPの件数 |
| --- | ---: | ---: |
| `panel_records.yaml` | 138 | 498 |
| `kanji_records.yaml` | 2,698 | 2,698 |
| `history_names.yaml` | 256 | 256 |
| `random_names.yaml` | 256 | 256 |

パネルのテーブルには、選択する文字だけでなくラベルや操作説明も入っています。
ランダム名は128件ずつの2組です。各エントリに元の番号、テーブル先頭からの
オフセット、バイト列を残します。終端やパディングも含め、同じ文字列や空の
エントリも元の位置のまま出力します。

北米版にも、日本版と同じ漢字テーブルが丸ごと残っています。
北米版のカテゴリ対応表は10件すべてが未割り当てです。日本版は50枠あり、
そのうち6枠が空きで、44組の漢字を選べます。両版にある45個の境界値が
この44組の範囲を表しています。

日本版の文字列は、同じバージョンのCLOADの文字表でデコードします。
`make splat VERSION=jp`でそのblobも抽出されます。文字表はGNAME自身には
入っていないため、バイトマップに出所を記録します。北米版は英語の文字コードで読み、
パネルの操作説明に含まれる辞書コードを展開します。北米版の文字表には残された
漢字の対応がないので、漢字は`{1D D4}`のようにコードを表示します。
日本版では、この例は「阿」と読めます。2バイト文字の2バイト目がゼロでも、
そこを文字列の終端と取り違えないようにします。

## データと実行時領域

データblobはUSが51,992バイト、JPが53,428バイトです。
既存のBSSが始まる`g_custom_name_buf`の直前までを含みます。
実行時のバッファは引き続き`gname.c`が持ち、USは296バイト、JPは292バイトです。

両版とも全バイトの用途を区分できています。USには7フレームの文字追加
アニメーションの後に4バイトのゼロパディングがあり、JPはアニメーション直後で
終わります。どちらも`unknown/`フォルダは不要です。読み取り後に意味の分からない
非ゼロのバイト列が残った場合は、そこへ変更せず保存します。

[`gname.py`](../../../../tools/overlays/gname.py)も、ほかのオーバーレイ抽出ツールと
同じ作りです。境界はシンボルから求め、リソースごとの読み取り処理とバイトマップを
使います。形式の解析には`tools/assets/`の既存パーサを再利用します。
アニメーションのYAMLには各フレームの3スロットすべてを残します。
グリフ番号ゼロのスロットは非表示で、フレームの表示時間に使うのは最初のスロットの
制御バイトだけです。単位は描画処理の更新回数です。
抽出結果を編集しても、ビルドがリンクするデータは変わりません。
