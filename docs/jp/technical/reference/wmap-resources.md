# WMAPのリソース

[日本語一覧](../../README.md) | [抽出ツール](../../../../tools/data/overlays/README.md) | [English](../../../en/technical/reference/wmap-resources.md)

WMAPはワールドマップです。アーティファクトの配置、アーティファクトを選ぶ
回転表示、土地の間の移動、マップのミニゲーム、土地ごとの演出を担当します。
両バージョンのYAMLでは、初期値を持つデータを1つの`wmap_data` databinに
まとめています。このblobはコードの直後からオーバーレイの末尾まで続きます。
ビルドでは元のバイト列をそのままリンクし、別の抽出ツールで中身を読めるようにします。

```sh
make splat
make extract-wmap

make splat VERSION=jp
make extract-wmap VERSION=jp
```

出力先は`assets/exports/<version>/overlays/wmap/`です。
`WMAP_OUTPUT=/path/to/new-folder`で別の場所を指定できます。
既存のフォルダは上書きしません。すべて読み終えてから一時フォルダに書き込み、
完了した時点で出力先へ移動します。書き込みに失敗した場合は一時フォルダを削除します。

## 出力されるもの

| パス | 内容 |
| --- | --- |
| `byte-map.yaml` | データblobの全範囲と、それぞれの出力先 |
| `tables/*.yaml` | 56個の固定テーブル。スプライトやプリミティブのテンプレート、ミニゲームのラウンド、情報パネル、土地テクスチャの枠、アーティファクトの画像と移動経路、土地の属性、地名ラベル、背景の形状 |
| `sounds/sound_01.akao`から`sound_63.akao` | 元のAKAO効果音バッファ63個 |
| `sounds/sounds.yaml` | 効果音ID、サイズ、各バッファのエントリ |
| `scripts/input_scripts.yaml` | 3つの自動入力スクリプト。デコード結果と元のバイト列 |
| `handlers/*.yaml` | 39個のソースファイルにある453個のステップテーブル。各エントリは関数名で表示 |
| `unknown/` | まだ何も名前を付けていない136バイトの隙間。変更せずに保存 |

どのテーブルのYAMLにも、シンボル名、レコード形式(Pythonの`struct`表記、
リトルエンディアン)、件数、デコードした行、コードでの使われ方の短い説明、
元のバイト列が入ります。フィールド名は、そのテーブルを読むCの型から取っています。
ソースでまだ`D_<アドレス>`と呼ばれているテーブルは、ファイル名もそのままです。
名前のアドレスはUS版のものです。JPのシンボルファイルは同じ名前をJPのアドレスで使います。

blobの大半はデータではありません。US版の先頭79,672バイト(JP版は79,668バイト)が
以下のテーブルで、残りのUS版898,584バイト(JP版898,576バイト)は実行時の変数と
バッファです。ディスク上ではすべてゼロなので、バイトマップに1つの範囲として記録し、
ファイルには書き出しません。

## 配置

オフセットはblobの先頭から数えます。JPのデータは全体がまとめてずれているだけなので、
オフセットは両版で同じです。blobの先頭はUS版が`0x800C4588`、JP版が`0x800C465C`です。

| オフセット | シンボル | 内容 |
| --- | --- | --- |
| `0x0` | `g_wmap_game_continue_prompt`ほか6個 | ミニゲームの案内、スコア、カウントダウンの`SPRT`テンプレート |
| `0x8C` | `g_wmap_game_spawn_patterns` | 8ラウンドそれぞれで、9つの土地のどれがせり上がるか |
| `0xD4` | (効果音バッファ) | 63個のAKAO効果音バッファ |
| `0x6C74` | `g_wmap_sfx_buffers` | 効果音ごとのポインタ |
| `0x6D70` | `g_wmap_information_glyphs` | 情報パネルのグリフ、配置、グループ |
| `0x7BDC` | `g_wmap_artifact_images` | 64個のアーティファクトのテクスチャ範囲と描画オフセット |
| `0x8770` | `g_wmap_artifact_pickup_frames` | アーティファクトを取り出す経路の740フレーム。続いて戻す経路の280フレーム |
| `0xB844` | `g_wmap_land_attributes` | 64個のアーティファクト。それぞれ8つの精霊の強さとフラグのワード |
| `0xBCCC` | `D_800D0254` | 地名ラベルの幅。両版で内容が違う唯一のテーブル |
| `0xBFBC` | `g_wmap_input_scripts` | 直前にある3つの入力スクリプトへのポインタ |
| `0xC170` | `g_wmap_menu_triangles` | メニューカーソルの28個のグーローシェーディング三角形 |
| `0xC4E4` | `g_wmap_sprite_textures` | 48個のスプライト用テクスチャページとパレット |
| `0xCA4C` | `D_800D0FD4` | 背景の三角形の頂点、三角形、座標バッファ |
| `0x106CC` | `D_800D4C54`以降 | 土地の演出とイベントのステップテーブル |

プリミティブのテンプレートは、libgpuのパケット(`SPRT`、`POLY_FT4`、`POLY_G4`、
グーローシェーディングの三角形)をそのまま格納したものです。コードはこれを
パケットバッファにコピーしてから書き換えます。タグのワードも出力するので、
YAMLで格納された値をそのまま確認できます。色はテンプレートの値で、
いくつかは実行時にフェードや色調の変更がかかります。

## 効果音

`g_wmap_sfx_buffers`には63個のポインタがあります。効果音ID Nはエントリ N - 1の
バッファを再生します(`wmap_resource_support.c`を参照)。そのためファイル名も
効果音IDで番号を振っています。各バッファは、`akao_sfx_play_list`が読む
AKAO効果音リストです。

| オフセット | サイズ | 内容 |
| --- | ---: | --- |
| `0x0` | 4 | `AKAO` |
| `0x4` | 4 | エントリ数 |
| `0x8` | 4 | `akao_bank_find_slot`で探すバンクのプログラムキー |
| `0x10` | エントリごとに4 | `0x20`から数えたエントリのオフセット |
| `0x20` | | エントリとシーケンスデータ |

各エントリには、チャンネルのシーケンスごとに1つずつ、計2つのu16オフセットがあります。
`0xFFFF`はそのチャンネルにシーケンスがないことを表します。`sounds.yaml`は
各エントリを一覧にし、2つのオフセットをバッファ内の位置に変換します。
シーケンスのバイト列は`.akao`ファイルに残し、再生はしません。
63個のバッファはUSとJPで完全に同じです。

## 自動入力スクリプト

WMAPは、コントローラ入力の代わりにスクリプトで自分を操作できます。
マップを開いたときに土地のイベント0、1、28が保留されていると、それぞれ
スクリプト1、2、3が始まります(`wmap_main.c`を参照)。各スクリプトは
`wmap_step_input_script`が読むs16のワードの並びです。

| ワード | 意味 |
| --- | --- |
| `N buttons` | `buttons`をNフレーム押し続ける(N > 0) |
| `0 0` | 実際のボタンが押されるまで待つ |
| `0 mask` | `mask`にビット`0x800`があれば、残りのビットのボタンを待つ。それ以外の値ではスクリプトを止める |
| `-2 command [argument]` | コマンドを実行 |
| `-1` | スクリプトの終わり |

コマンド名はソースの`WMAP_SCRIPT_`列挙から取っています。`IMAGE`、`BUTTON_MASK`、
`VISIBILITY`は引数のワードを1つ取り、`WAIT_`系のコマンドと`FIND_HOME`は取りません。
`IMAGE`はID指定でCDのファイル(例えば4435、`0x1153`)をVRAMに読み込み、案内画像として
表示します。引数がゼロ以下なら案内画像を消します。USとJPのスクリプトの違いは
ボタンのワードだけです。スクリプトが押す決定ボタンは、US版が×(`0x0040`)、
JP版が○(`0x0020`)です。`wmap_main.h`の`WMAP_PAD_CONFIRM`と同じ入れ替えです。

## ステップテーブル

WMAPの土地の演出やイベントの多くは、ステップテーブルで動いています。
関数ポインタの配列で、シーケンスが1ステップごとに1エントリずつ進みます。
抽出ツールは`src/overlays/wmap`の宣言(`void (*name[])(void)`または
`WmapHandler name[]`)からテーブルを見つけるので、`handlers/`の各ファイルは
1つのCファイルに対応します。各エントリは関数名で書き出します。
多くはソースでまだ`func_<アドレス>`という名前です。このアドレスはUS版のもので、
JPでも同じ名前を使います。

nullのエントリはゼロのワードです。US版の最後のテーブル
`g_wmap_effect35_emitter_b_steps`には、実行時の変数が始まる前に
nullのワードが1つ余分にあります。JP版にはありません。
土地の演出18にある`D_800D4DB4`のエントリの1つは、コードではなくWMAP自身のデータ
(スプライトアクター12)を指しています。隠さずに`{data: g_wmap_sprite_actors+0x210}`として残します。
サイズが分かっているシンボルの内側を指すアドレスは、シンボル名にオフセットを付けて表します。

## バイトマップに残すもの

| バージョン | データblob | ゼロで埋められた実行時領域 | 未解釈 | パディング |
| --- | ---: | ---: | ---: | ---: |
| US | 978,256バイト | 898,584バイト | 1ファイル、136バイト | 8バイト |
| JP | 978,244バイト | 898,576バイト | 1ファイル、136バイト | 8バイト |

バイトマップは全バイトを扱い、それぞれの範囲を一度だけ数えます。
パディングは入力スクリプトの後にあるゼロのバイトです。Cの配列に固定の長さがない
テーブルは、次のリソースまでの格納された範囲をすべて含みます。そのため、
`g_wmap_spirit_sequence_bounds`の後の3バイトのように、末尾に整列用のバイトを
含むものがあります。

読み取りと出力は[`wmap.py`](../../../../tools/data/overlays/wmap.py)、テーブルの形式は
[`wmap_tables.py`](../../../../tools/data/overlays/wmap_tables.py)にあります。
コードより前にあるrodataは、2つの4バイトの整列用blobも含めて変更していません。
抽出結果を編集しても、ビルドがリンクするデータは変わりません。
