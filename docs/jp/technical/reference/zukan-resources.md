# ZUKANのリソース

[日本語一覧](../../README.md) | [抽出ツール](../../../../tools/data/overlays/README.md) | [English](../../../en/technical/reference/zukan-resources.md)

ZUKANは図鑑の画面です。ランド、アーティファクト、モンスターなどの分類の一覧と、
項目を開いたときのページを表示します。画面に出るものは、ほとんどがオーバーレイの中に
入っています。2つのテクスチャ、すべての項目名と分類名、枠やボタンのスプライトです。
ページだけは別で、1ページずつ独立したCDリソースになっていて、項目を開いたときに
読み込まれます。

これらはすべて書き出せます。

```sh
make splat
make extract-zukan

make splat VERSION=jp
make extract-zukan VERSION=jp
```

出力先は`assets/exports/<version>/overlays/zukan/`です。別の場所にしたいときは
`ZUKAN_OUTPUT=/path/to/new-folder`を指定してください。ただし、まだ存在しない
フォルダに限ります。途中で失敗しても、書きかけの出力は残りません。
出力は読むためのもので、編集してもビルドで作られるものは変わりません。

| パス | 内容 |
| --- | --- |
| `archive/archive.yaml` | アーカイブのヘッダーと、各セクションの中身 |
| `images/page/`、`images/border/` | 元の2つのTIMと、パレットごとのPNG |
| `images/sprites/` | UIスプライト21件のデコード結果と、それぞれのPNG |
| `text/entry_names.yaml` | 項目名1,014件 |
| `text/category_names.yaml` | 12件の分類名 |
| `tables/categories.yaml` | 各分類がどこから始まり、どこで終わるか |
| `tables/history_groups.yaml` | 世界事典の6つのグループ |
| `tables/entries.yaml` | 全1,018件の項目。名前、分類、ページ |
| `tables/display_order.yaml` | 一覧に並べる順番 |
| `byte-map.yaml` | それぞれがどこから来たか |

項目と分類はUSとJPで同じです。

## テクスチャ

データの先頭には小さなアーカイブがあります。件数の4と、アーカイブの先頭から数えた
4つのオフセットで始まります。

| セクション | オフセット | 内容 |
| ---: | --- | --- |
| 0 | `0x14` | ページテクスチャ。(320, 0)へ転送 |
| 1 | `0x8234` | 枠テクスチャ。(832, 256)へ転送 |
| 2 | `0x10454` | 項目名 |
| 3 | US `0x12C70`、JP `0x123E0` | 分類名 |

ページテクスチャには、羊皮紙のページとその縁、PREV / NEXT / ENDのボタンが
入っています。枠テクスチャは、その周りを囲む装飾の枠です。どちらも256 x 256で、
1ピクセル4ビットです。

パレットの扱いが少し変わっています。どちらのTIMもCLUT全体をVRAMの同じ行(0, 498)へ
転送し、ページテクスチャが後なので、枠テクスチャのパレットは上書きされてしまいます。
枠も含めて、画面に出るものはすべてページテクスチャの色で描かれます。ゲームで
実際に見える色なので、PNGもその色を使っています。中身があるのはパレット0から5だけで、
PNGもその分だけです。枠テクスチャ本来のパレットが必要なら、TIMファイルに残っています。

図鑑を閉じるときには、後片付けが必要なことがあります。枠テクスチャの転送先(832, 256)は、
フィールドのマップのテクスチャが十分に横長だと、その上に重なります。その場合ZUKANは、
戻る前にCDリソース`0x5E3`から該当する列を読み直します。このリソースに入っているのは、
ホームのマップ`MHM_ALC2`の列だけです。

## 名前

項目名と分類名は、通常のu16オフセット表の形式です（[テキストテーブル](text-tables.md)を参照）。
項目0はダッシュが並んでいるだけで、空の名前もかなりあります。USは274件、JPは266件です。
日本版のテキストはCLOADの文字表でデコードします。文字表は`make splat VERSION=jp`で
ほかと一緒に抽出されます。北米版の辞書コードや制御コードは、ほかの出力と同じく
波括弧で表示します。

## UIスプライト

スプライトのレコードは12バイトで21件あります。まとめた2つのワードと、画面上の位置です。

| ビット | 内容 |
| --- | --- |
| ワード0、ビット0から7 | テクスチャ。0がページ、1が枠 |
| ワード0、ビット8から15 | U |
| ワード1、ビット0から7 | V |
| ワード1、ビット8から13 | パレットの行 |
| ワード1、ビット14から22 | 幅 |
| ワード1、ビット23から31 | 高さ |
| u16、u16 | 画面上のXとY |

画面では、どのスプライトも格納されたXより8ピクセル右に描かれます。

スプライト0から5は、ページの下に並ぶ操作ボタンです。前の項目へ移るときは0、
次の項目へ移るときは3、一覧に戻るときは5が光ります。一覧の表示中は0から3が
暗くなります。6から20は枠とページを組み立てます。PNGにはこうした色の変化は
入っていません。

## 分類と項目

各項目には番号があります。この番号で`entry_names.yaml`の名前と、`entries.yaml`の
ページが決まります。ページの値がNならCDリソース`0xBFC` + Nを開き、0ならページは
ありません。ページがないのは項目0だけです。

分類の境界は13個あります。分類Nには、N番目の境界から次の境界の手前までの項目が
並びます。画面側で3つの分類を変えています。

- 人物図鑑は480ではなく454で終わります。
- 世界事典は640ではなく576で終わります。
- 必殺技図鑑には、自分の項目の後ろに項目454から479が追加されます。

なので、境界だけを見ると454から479は人物のように見えますが、実際は必殺技図鑑に
並ぶアビリティです。項目576から639はどの一覧にも並びません。アーティファクトの
2ページ目です（後で説明します）。

世界事典はさらに6つのグループに分かれていて、オフセットは項目480から数えます。
出力には各グループの項目を載せています。

並び順はどの一覧も表示順のリストで決まります。画面はこのリストを先頭から見ていき、
その分類に入る項目を拾います。リストに入っていない項目は一覧に出てきません。
リストは718か所で、`0x400`で終わります。

## 解放ビット

項目を開けるかどうかは、セーブデータの図鑑ビットで決まります。
[セーブファイル](save-file.md)のオフセット`0x3254`にある1,024ビットです。
解放されていない項目も一覧の行は使いますが、仮の表示が出て、開くことはできません。

| 分類 | 項目 | ビット |
| --- | --- | --- |
| ランド | 1-64 | `0x200` + (項目 - 1) |
| アーティファクト | 65-128 | `0x240` + (項目 - 65)、または`0x280` + (項目 - 65) |
| モンスター | 230-308 | 項目 - 230 |
| モンスター | 310-349 | 300 + (項目 - 310) |
| 人物図鑑 | 350-453 | 100 + (項目 - 350) |
| 必殺技図鑑（アビリティ） | 454-479 | `0x3C8` + (項目 - 454) |
| 世界事典 | 480-575 | グループごとに1つ、`0x122`から`0x127` |
| サボテンくん日記 | 640-739 | 200 + (項目 - 640) |
| 必殺技図鑑 | 750-1012 | `0x2C0` + (項目 - 750) |

モンスター309はいつでも開けます。武器・防具・楽器、アイテム、植物、
ゴーレム製作１０のツボは何も調べないので、並んだ項目はすべて開けます。

いくつかの分類は、調べる直前に自分でビットを立てます。ランドとアーティファクトは
ランドの記録から立てます。必殺技図鑑は、覚えたアビリティ（US版の名前でJump、Defend、
LungeからSlideまで、最後にFlip Kick）からアビリティのビットを、
武器ごとに覚えた必殺技から必殺技のビットを立てます。

ビットが2つあるのはアーティファクトだけです。`0x240`のほうは置いたランドごとに立ち、
`0x280`のほうはランドの別のフラグから立ちます。どちらかが立っていれば開けて、
`0x280`のほうが立っているときは2ページ目、つまり511件先の項目が開きます。
なので、アーティファクト65は項目576のページを開きます。
