# ZUKANのリソース

[日本語一覧](../../README.md) | [抽出ツール](../../../../tools/overlays/README.md) | [English](../../../en/technical/reference/zukan-resources.md)

ZUKANは図鑑の画面です。ランド、アーティファクト、モンスター、人物、世界事典などの
一覧と、各項目のページを表示します。両バージョンのYAMLでは、画像、名前、
スプライトの配置をコードの後ろにある1つの`zukan_data` databinにまとめています。
各分類にどの項目を並べるかを決める表は、コードの前にある1つの
`zukan_entry_tables` rodatabinに入っています。ビルドでは元のバイト列をそのまま
リンクし、別の抽出ツールで中身を見られるようにします。

```sh
make splat
make extract-zukan

make splat VERSION=jp
make extract-zukan VERSION=jp
```

出力先は`assets/exports/<version>/overlays/zukan/`です。
`ZUKAN_OUTPUT=/path/to/new-folder`で別の場所を指定できます。
既存のフォルダは上書きしません。すべて読み終えてから一時フォルダに書き込み、
完了した時点で出力先へ移動します。書き込みに失敗した場合は一時フォルダを削除します。

## 出力されるもの

| パス | 内容 |
| --- | --- |
| `byte-map.yaml` | データblobと項目表のrodata内の全範囲 |
| `archive/archive.yaml` | アーカイブのヘッダー。4つのセクションのオフセットと中身 |
| `images/page/image.tim` | 元の256 x 256、4ビットのページテクスチャ |
| `images/border/image.tim` | 元の256 x 256、4ビットの枠テクスチャ |
| `images/*/image.yaml` | 格納時の配置、VRAMへの転送位置、格納されたパレット値 |
| `images/*/palette_00.png`から`palette_05.png` | 画面で使う6つのパレットで表示した各テクスチャ |
| `images/sprites/sprites.yaml` | 固定のUIスプライト21件。元のワードと並べてデコード |
| `images/sprites/00.png`から`20.png` | テクスチャから切り出した各スプライト |
| `text/entry_names.yaml` | 項目名1,014件。オフセットと元のコード付き |
| `text/category_names.yaml` | 12件の分類名 |
| `tables/categories.yaml` | 各分類が項目リストのどこから始まり、どこで終わるか |
| `tables/history_groups.yaml` | 世界事典の6つのグループと、それを解放するビット |
| `tables/entries.yaml` | 1,018件の項目。名前、分類、ページのCDリソース |
| `tables/display_order.yaml` | 一覧に並べる順番。718か所 |

両版とも、33枚のPNGと11個のYAML、2つのTIMを出力します。
項目と分類の件数はUSとJPで同じです。

## アーカイブ

`g_zukan_resource_archive`は、件数4と4つのオフセットで始まります。
オフセットはどれもアーカイブの先頭から数えます。

| セクション | オフセット | 内容 |
| ---: | --- | --- |
| 0 | `0x14` | ページテクスチャ。(320, 0)へ転送 |
| 1 | `0x8234` | 枠テクスチャ。(832, 256)へ転送 |
| 2 | `0x10454` | 項目名 |
| 3 | US `0x12C70`、JP `0x123E0` | 分類名 |

ページテクスチャには、羊皮紙のページとその縁、PREV / NEXT / ENDのボタンが
入っています。枠テクスチャには、ページを囲む装飾の枠が入っています。
どちらのTIMも、CLUTの256色すべてを(0, 498)の同じ行へ転送し、ページテクスチャが
後に転送されます。そのため枠テクスチャ自身のパレットは画面に出ることがなく、
スプライトはすべてページテクスチャのパレットで描かれます。プレビューもその色を
使います。色が入っているのはパレット0から5だけで、空のパレットのPNGは作りません。
それでもTIMファイルには、枠テクスチャのものも含めて元のパレット値を残します。

2つのテキストセクションは、通常のu16オフセット表の形式です
（[テキストテーブル](text-tables.md)を参照）。項目名の0番はダッシュの並びで、
USは274件、JPは266件の名前が空です。日本版のテキストは、同じバージョンの
CLOADの文字表でデコードします。`make splat VERSION=jp`でそのblobも抽出され、
文字表の出所はバイトマップに記録されます。北米版の辞書コードや制御コードは、
ほかの出力と同じく波括弧で表示します。

画面を閉じるとき、CDリソース`0x5E3`を同じバッファに読み込み、
枠テクスチャがあった(832, 256)へ転送することがあります。
アーカイブがこのバッファに入っているのは、それまでです。

## UIスプライト

`g_zukan_ui_sprites`は12バイトのレコード21件です。
2つのまとめたワードと、画面上の位置が入っています。

| ビット | 内容 |
| --- | --- |
| ワード0、ビット0から7 | テクスチャ。0がページ、1が枠 |
| ワード0、ビット8から15 | U |
| ワード1、ビット0から7 | V |
| ワード1、ビット8から13 | パレット。(0, 498)の共有CLUT内の番号 |
| ワード1、ビット14から22 | 幅 |
| ワード1、ビット23から31 | 高さ |
| u16、u16 | 画面上のXとY。描画時にXへ8を足します |

スプライト0から5は、下に並ぶページの操作ボタンです。前の項目へ移るときは0、
次の項目へ移るときは3、一覧に戻るときは5が光ります。一覧の表示中は、
0から3が暗くなります。6から20は枠とページを組み立てます。
PNGにはこうした色の変化は入っていません。

## 分類と項目

各項目には1つの番号があります。この番号で`entry_names.yaml`の名前と、
`g_zukan_entry_values`の値が決まります。値がゼロでなければ、
CDリソース`0xBFC` + 値をその項目のページとして開きます。ゼロならページはありません。
両版とも、ゼロなのは項目0だけです。

`g_zukan_category_ranges`には13個の項目番号が入っています。分類Nには、
N番目の番号から次の番号の手前までの項目が並びます。画面側で3つの分類を変えています。

- 人物図鑑（7）は480ではなく454で終わります。
- 世界事典（8）は640ではなく576で終わります。
- 必殺技図鑑（11）には、自分の範囲の後ろに項目454から479が追加されます。

つまり、人物の範囲にある454から479は実際には必殺技です。
項目576から639はそれ自体ではどの一覧にも並ばず、
アーティファクト用の2つ目の値として使われます。

開ける項目は、セーブデータの図鑑ビットで決まります。
[セーブファイル](save-file.md)のオフセット`0x3254`にある1,024ビットです。
ランド、アーティファクト、モンスター、人物、サボテンくん日記、必殺技の各図鑑は、
項目番号から決まった距離にあるビットを項目ごとに1つ調べます。
世界事典は、後で説明するグループごとに1つのビットを調べます。
武器・防具・楽器、アイテム、植物、ゴーレム製作１０のツボの各図鑑はビットを調べず、
並んだ項目はすべて開けます。まだ解放されていない項目も一覧の行は使いますが、
名前の代わりに仮の表示が出て、開くことはできません。アーティファクトは2つの
ビットを調べます。2つ目のビットが立っていると511件先の値を使うため、
アーティファクト65は項目576のページを開きます。

`g_zukan_group_ranges`は世界事典を6つのグループに分けます。オフセットは項目480から
数えます。各グループの項目は、そのビット（`0x122`から`0x127`）が立つまで
解放されません。出力には各グループの項目範囲とビットを載せています。

`g_zukan_display_order`は一覧に並べる順番です。画面はこのリストを先頭から見ていき、
その分類に入る項目を拾います。ここに入っていない項目は一覧に並びません。
718か所の後、`0x400`で終わります。

## 配置

データblobはUSが79,456バイト、JPが77,272バイトです。アーカイブとスプライトの後の
最後の2,140バイトは、画面の変数と表示中の項目リストです。ディスク上ではすべてゼロなので、
バイトマップには載せますがファイルは書きません。項目表のrodataは両版とも3,556バイトで、
最後に2バイトのパディングがあります。

表とCのコードの間にある660バイトは、オーバーレイの入口の関数`zukan_run`です。
これはコードなので、専用の`zukan_run_code` rodatabinに入れてあり、出力はしません。

両版とも、バイトマップは全バイトを扱っています。JPには不明な範囲がありません。
USには1つあり、分類名の後ろの6バイトを`unknown/8015741A.bin`に保存します。
[`zukan.py`](../../../../tools/overlays/zukan.py)は、ほかの抽出ツールと同じく、
リソースの読み取り処理、`Part`レコード、書き込み処理を分けています。
抽出結果を編集しても、ビルドがリンクするデータは変わりません。
