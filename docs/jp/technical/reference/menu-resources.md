# MENUのリソース

[日本語一覧](../../README.md) | [抽出ツール](../../../../tools/overlays/README.md) | [English](../../../en/technical/reference/menu-resources.md)

MENUは、フィールドから開くゲーム内メニューです。左側のノードツリー、
そこから開くページ、アイテムや装備の一覧、画面下のヘルプ行を担当します。
テクスチャ、アイコン、テキスト、ページのレイアウト、いくつかの小さなテーブルは、
コードの後ろにある1つのデータblobに入っています。両バージョンのYAMLでは、
これを1つの`menu_data` databinにまとめています。ビルドでは元のバイト列をそのまま
リンクし、別の抽出ツールで中身を見られるようにします。

```sh
make splat
make extract-menu

make splat VERSION=jp
make extract-menu VERSION=jp
```

出力先は`assets/exports/<version>/overlays/menu/`です。
`MENU_OUTPUT=/path/to/new-folder`で別の場所を指定できます。
既存のフォルダは上書きしません。すべて読み終えてから一時フォルダに書き込み、
完了した時点で出力先へ移動します。書き込みに失敗した場合は一時フォルダを削除します。

## 出力されるもの

| パス | 内容 |
| --- | --- |
| `byte-map.yaml` | blob内の全範囲。アドレス、オフセット、サイズ付き |
| `image/asset.bin` | 格納されたままのテクスチャリソース。短いヘッダ、TIM、2段目のパレット行 |
| `image/image.tim` | 256 x 256、4ビットのTIM単体 |
| `image/image.yaml` | ヘッダの値、格納時のTIM配置、全パレット |
| `image/palette_00.png`から`palette_1F.png` | 32個のパレットそれぞれで表示したテクスチャ全体 |
| `image/grid.png`、`image/grid.yaml` | 29件のスプライトレコードから組み立てた羊皮紙風の背景 |
| `icons/icons.yaml` | 全113件のアイコンレコード。テクスチャ上の矩形とパレットコード |
| `icons/001.png` ... | 106個のアイコン。それぞれ自分のパレットで切り出したもの |
| `text/resource.bin` | 元のテキストリソース全体 |
| `text/resource.yaml` | 34個のテーブルのオフセット、サイズ、名前 |
| `text/00_general.yaml` ... `text/33.yaml` | テーブルごとに1ファイル。全エントリ、オフセット、元のバイト列付き |
| `content/nodes.yaml` | ツリーの44ノード。コンテンツグループ、項目数、開くアイテムセット |
| `content/group_ids.yaml` | 各ノードのコンテンツグループ |
| `content/item_counts.yaml` | 37個のコンテンツグループそれぞれの項目数 |
| `content/groups.yaml` | 各グループの項目数と8個のアクションコード |
| `content/item_sets.yaml` | ノードが参照する24個のアイテムセット。合計1,000項目 |
| `tables/label_ids.yaml` | 一部のページがツリーに差し込むラベルIDと、それを参照するシンボル |
| `tables/input_scripts.yaml` | 16本の入力スクリプト。1フレームごとのパッド入力 |
| `tables/cursor_icons.yaml` | カーソルアニメーションで使う3つのアイコンID |

テーブルのファイルには元のバイト列を`bytes`に残し、テキストのファイルには
各文字列の元のバイト列をデコード結果の隣に残します。デコードした値が
間違っていても、元のデータは失われません。

## 配置

blobはコードの直後から始まります。下の表はRAM上のアドレスです。
`menu_data.databin.bin`内のオフセットはバイトマップに記録されています。

| リソース | US | JP | サイズ |
| --- | --- | --- | --- |
| アイコンの矩形 | `0x8014FBF4` | `0x8014FBE8` | 452 |
| アイコンのパレットコード | `0x8014FDB8` | `0x8014FDAC` | 113 |
| コンテンツの項目数 | `0x8014FE2C` | `0x8014FE20` | 37 |
| コンテンツのアクションコード | `0x8014FE54` | `0x8014FE48` | 296 |
| コンテンツのアイテムセット | `0x8014FF7C` | `0x8014FF70` | 8,000 |
| テキストリソース | `0x80151EBC` | `0x80151EB0` | US 58,276、JP 55,948 |
| テクスチャリソース | `0x80160260` | `0x8015F93C` | 33,836 |
| ラベルID | `0x80168690` | `0x80167D6C` | 60 |
| コンテンツグループID | `0x801686CC` | `0x80167DA8` | 44 |
| コンテンツテーブル | `0x801686F8` | `0x80167DD4` | 176 |
| 入力スクリプト | `0x801687A8` | `0x80167E84` | 768 |
| 背景グリッドのスプライト | `0x80168AA8` | `0x80168184` | 348 |
| カーソルのアイコンID | `0x80168C04` | `0x801682E0` | 3 |
| 実行時の変数 | `0x80168C08` | `0x801682E8` | 11,732 |

間にあるのはゼロのパディングだけで、USは11バイト、JPは15バイトです。
最後の11,732バイトは、メニューの変数、ノードツリー、ウィンドウスロット、
メモリーカード用のバッファです。ディスク上ではすべてゼロなので、バイトマップに
範囲だけを記録し、ファイルは書き出しません。どちらのバージョンにも`unknown/`
フォルダは必要ありません。認識できないゼロ以外のバイトがあれば、アドレスを名前にして
そのまま保存します。

## テクスチャとパレット

テクスチャリソースの先頭は3ワードです。エントリ数の2、TIMのオフセット(12)、
TIMの後ろに続く2段目の256色パレット行のオフセットが並びます。TIMは256 x 256
ピクセル、1ピクセル4ビットで、256色を持ちます。メニューはピクセルを(320, 0)へ、
TIMの色を1行にして(0, 498)へ、2段目を(0, 499)へ転送します。

アイコンと背景のスプライトは、1バイトのコードでパレットを選びます。
上位4ビットが行、下位4ビットがその行の中の16色パレットです。たとえば`0x0B`は
TIM自身の色のパレット11、`0x11`は2段目のパレット1です。プレビューのPNGも
このコードで名前を付けています。色0は透明、それ以外は不透明で表示します。
転送時にはゼロ以外の色にSTPビットを立てますが、出力するTIMは格納された値のままです。

USとJPのテクスチャの違いは、(64, 80)にある12 x 8ピクセルの1か所だけで、
パレットは同じです。JPでは5件のアイコンレコード(34から37と42)が別のセルや
パレットを使い、46件のコンテンツ項目が1、2ピクセルずれています。
背景グリッド、グループ、項目数、ラベル、スクリプトのテーブルは同一です。

## アイコンと背景グリッド

アイコンレコードは4バイトで、テクスチャ上のU、V、幅、高さです。
並行する配列が各アイコンのパレットコードを持ちます。番号0、25、32、96から99は
空です。`icons.yaml`には番号を残しますが、PNGは作りません。カーソルの
アニメーションはアイコン0x6B、0x6C、0x6Dを使い、`tables/cursor_icons.yaml`に
入っています。

背景は29個のスプライトで、1件12バイトです。まとめたU/V、予約の2バイト、
画面上のX、Y、幅、高さが続きます。17番以降はパレット`0x01`、それより前は
`0x00`を使います。`grid.png`はそれらを画面上の位置に並べたもので、
312 x 224ピクセルです。ゲーム中の色調変更は再現しません。

## テキストテーブル

テキストリソースは、テーブル数(34)、リソース先頭からの34個のバイトオフセット、
テーブル本体の順に並びます。各テーブルはいつもの形式で、u16のオフセット表の後ろに
ゼロ終端の文字列が続きます。詳しくは[テキストテーブル](text-tables.md)を
見てください。すべてのテーブルを、そのバージョンの2バイトコードで解析します。
北米版の辞書コードや制御コードは波括弧で表示します。日本版のテキストは、
同じバージョンのCLOADの文字表でデコードし、文字表の出所をバイトマップに記録します。

テーブル名は[`menu_internal.h`](../../../../src/overlays/menu/menu_internal.h)の
`MenuTextTable`列挙型から取ります。そこに名前がないテーブルは、`02.yaml`のように
番号だけになります。名前の中には、まだ中身と合っていないものがあります。
テーブル3は呪文名と呼ばれていますが、中身はジャンプやガードといった動作です。
アビリティのヘルプと名前と呼ばれているテーブル4と5には、ポストから始まる
アーティファクトが入っています。

自分のテーブルの外を読むエントリもあります。US版のテーブル3では、テーブル内を
指すオフセットは最初の82件だけです。残りの174件はすべてテーブルの終端を指すので、
テーブル4の先頭のバイトを読みます。これらのエントリには`outside_table: true`を
付けています。

テーブル19と20は、両バージョンとも番号付きの日本語の仮テキスト
(「モンスター技００」とそのヘルプ)です。日本語の文字コードで書かれているので、
US版の出力では波括弧のコードとして表示されます。

## コンテンツページ

ツリーの44ノードは、それぞれコンテンツグループとコンテンツテーブルのポインタを
持ちます。ポインタが0ならページはありません。値1(ノード32)はページを開かず、
`g_menu_load_request`を立ててメニューを終了します。それ以外はアイテムセットを
指します。複数のノードが同じセットを共有することもあり、ノード0、3、6は
キャラクタースロットごとに同じセットを開きます。

コンテンツ項目は8バイトです。

| オフセット | サイズ | フィールド |
| --- | --- | --- |
| 0 | 2 | ビット0から8がX座標、9から11がスタイル、12から15が種類 |
| 2 | 1 | Y座標 |
| 3 | 1 | アクションの種類。項目を描くページが解釈します |
| 4 | 4 | パラメータ。意味はページによって違います |

種類5はサブメニューを開き、種類0xFはアクションを実行します。この2つの名前は
Cのdefineから取っています。種類5か0xFでスタイルが7の項目は、そのページの
アクティブな項目で、カーソルはそこから始まります。項目のアクションコードは
`groups.yaml`から決まります。行がノードのコンテンツグループ、列が項目のスタイルです。

`item_counts.yaml`はグループごとの項目数で、全部で37件です。34番は、
シーン種別が-1のときの項目数も兼ねています。その場合は値に1を足した4項目を
`g_menu_default_content_items`から読みます。どのアイテムセットも、すべて0の
項目から始まります。`item_sets.yaml`は、各セットの項目を次のセットの手前まで並べ、
それを使うノードも記録します。

## ラベルと入力スクリプト

`tables/label_ids.yaml`には60バイトのラベルIDが入っています。コードは
これを1つの先頭アドレスから読むのではありません。6つのベースを使い、それぞれを
アクションの種類、ノード番号、パーティー順のスロットで引きます。ベース同士は
重なっています。YAMLには各ベースのシンボルと、先頭のバイトを読む添字
`first_index`を記録します。たとえばUSの`0x80168659`のベースは、アクションの種類
0x37から0x54でしか引かれないので、先頭のバイトは添字55になります。

入力スクリプトは、1フレームに1つの16ビットのボタンマスクを`0xFFFF`まで再生します。
1本のスクリプトは24個分の枠を持ちます。スクリプト0は「スクリプトなし」を意味するので、
その行は読まれません。その48バイトはコンテンツテーブルの最後の12件で、出力でも
そちらに含めています。終端があるのはスクリプト1、2、3、4、5、6、10、11、12です。
残りはすべてゼロです。ボタン名はSDKの`libetc.h`から取ります。
