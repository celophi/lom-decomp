# GOSUBのリソース

[日本語一覧](../../README.md) | [抽出ツール](../../../../tools/overlays/README.md) | [English](../../../en/technical/reference/gosub-resources.md)

GOSUBは、アイテムの選択やロジックブロック、ペット、ゴーレム、卵の一覧など、
作成・育成に使う画面を持っています。両バージョンのYAMLでは、画像、テキスト、
テーブルを1つの`gosub_data` databinにまとめています。
コードの前にある装備分類の範囲は、小さな`gosub_groups` rodatabinに入っています。
ビルドでは元のバイト列をそのままリンクし、別の抽出ツールで中身を見られるようにします。

```sh
make splat
make extract-gosub

make splat VERSION=jp
make extract-gosub VERSION=jp
```

出力先は`assets/exports/<version>/overlays/gosub/`です。
`GOSUB_OUTPUT=/path/to/new-folder`で別の場所を指定できます。
既存のフォルダは上書きしません。すべて読み終えてから一時フォルダに書き込み、
完了した時点で出力先へ移動します。書き込みに失敗した場合は一時フォルダを削除します。

## 出力されるもの

| パス | 内容 |
| --- | --- |
| `byte-map.yaml` | データと装備分類のblob内の全範囲 |
| `image/image.tim` | 元の256 x 256、4ビットのUIテクスチャと16個のパレット |
| `image/image.yaml` | 格納時の配置、パレット値、グリフのプレビュー情報 |
| `image/palette_00.png`から`palette_0F.png` | 各パレットで表示したテクスチャ全体 |
| `image/glyphs/` | 79枚のグリフプレビュー。それぞれを16パレットすべてで表示 |
| `text/archive.bin` | 元のテキストアーカイブ全体 |
| `text/archive.yaml` | 12個のセクションのオフセット |
| `text/*.yaml` | デコードした文字列。番号、オフセット、元のコード付き |
| `portraits/archive.bin` | 元の件数、オフセット表、84件のポートレート |
| `portraits/portraits.yaml` | ポートレートの番号、分類、オフセット、パレット |
| `portraits/00.png`から`83.png` | 格納されたパレットで表示した48 x 48のポートレート |
| `font/image.tim`、`image.png`、`image.yaml` | 64 x 16のフォントTIM全体とプレビュー、配置情報 |
| `tables/glyph_metrics.yaml` | 空の3件も含む、全82件のグリフレコード |
| `tables/item_colors.yaml` | 色素材のアイテムID 37件に対応する色名の番号 |
| `tables/equipment_groups.yaml` | 武器、防具、楽器の開始番号と件数 |

両版とも、180枚のPNGと20個のYAML、元のリソースファイルを出力します。
UIテクスチャとグリフ情報は、USとJPのどちらもGOLEMが持つものと完全に同じです。
ポートレートは別のアーカイブで、番号0から64がペット、65から71がゴーレム、
72から83が卵です。

## テキストテーブル

両版のエントリ数は同じです。空のエントリや重複する文字列も、元の番号を保ちます。

| セクションのファイル | 件数 |
| --- | ---: |
| `item_names.yaml` | 256 |
| `item_descriptions.yaml` | 256 |
| `equipment_types.yaml` | 32 |
| `spirit_names.yaml` | 256 |
| `spirit_descriptions.yaml` | 256 |
| `logic_block_names.yaml` | 58 |
| `logic_block_descriptions.yaml` | 58 |
| `messages.yaml` | 57 |
| `pet_species.yaml` | 65 |
| `golem_types.yaml` | 7 |
| `instrument_spells.yaml` | 112 |
| `color_names.yaml` | 33 |

セクション名とメッセージのシンボル名は、
[`gosub_internal.h`](../../../../src/overlays/gosub/gosub_internal.h)から取得します。
セクションのオフセットはアーカイブ先頭から、文字列のオフセットは各セクションの
先頭から数えます。元のアーカイブにはオフセット表、終端、パディングも残します。

日本版のテキストは、同じバージョンのCLOADの文字表でデコードします。
`make splat VERSION=jp`でそのblobも抽出され、文字表の出所はバイトマップに記録されます。
北米版の辞書コードや制御コードは、FIELDやCLOADの出力と同じく波括弧で表示します。
装備分類の表では、武器が番号0から11件、防具が11から12件、楽器が23から4件です。

## 画像の見方

UIのグリフレコードにはパレットの指定がなく、描画時に呼び出し側が渡します。
各グリフのPNGには、パレット0から15を4列4行で並べます。
順番は左から右、上から下です。番号0、20、53はサイズがゼロなので、
YAMLには残しますが空のPNGは作りません。GOLEMとGOSUBは、
[`glyph_texture.py`](../../../../tools/overlays/glyph_texture.py)の同じ処理でプレビューを作ります。

PNGではパレット値ゼロを透明、それ以外を不透明にします。
実行時の色調変更、半透明合成、パレットの変更は適用しません。
元のTIMとポートレートデータは、STPビットを含めてパレット値を保ちます。
UIのTIMに格納された座標は、画像が(0, 0)、パレットが(0, 480)です。
GOSUBは画像を(320, 0)に転送し、256色を1行に並べて(0, 498)へ転送します。
別のフォント画像は(320, 240)、そのパレットは(336, 255)へ転送します。
この画像には、描画処理が使うパネルの角も含まれています。

## 以前の分割位置について

2つのシンボルがリソースの途中を指しています。
`g_gosub_portrait_archive`は、件数84を表すワードの4バイト後にあるオフセット表を
指します。以前の分割では件数のワードがテキストデータの末尾に入っていましたが、
これはポートレート側のデータです。出力するアーカイブはこのワードから始まり、
各オフセットもそこから数えます。

`g_gosub_font_texture`は、TIMの先頭から20バイト後にあるパレットを指します。
画像の転送では512バイトのピクセルデータを読みます。その最後の92バイトは、
`g_gosub_item_colors`の未使用の先頭部分にまたがっています。
このシンボルの位置で切ると画像の一部が失われるため、576バイトのTIM全体を出力します。
色名の参照に使うのはアイテムID 96から132の37バイトで、こちらは別に出力します。
バイトマップでは、それぞれの範囲を一度だけ数えます。

データblobはUSが149,616バイト、JPが149,228バイトです。
既存のBSSが始まる`g_gosub_frame_parity`の直前で終わります。
両版とも、実行時の変数やバッファ37,268バイトは`gosub.c`に残します。
装備分類のrodataは両版とも24バイトです。それ以外のrodataは元のC単位に残します。

ゼロのパディングと、UIのTIMやポートレートアーカイブ末尾の繰り返しワードも含め、
両版とも全バイトを扱えているため、`unknown/`フォルダは不要です。
意味の分からない非ゼロのデータが残った場合は、変更せずにそこへ保存します。
[`gosub.py`](../../../../tools/overlays/gosub.py)は、ほかの抽出ツールと同じく、
リソースの読み取り処理、`Part`レコード、書き込み処理を分けています。
抽出結果を編集しても、ビルドがリンクするデータは変わりません。
