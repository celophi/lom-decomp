# GOLEMのリソース

[日本語一覧](../../README.md) | [抽出ツール](../../../../tools/overlays/README.md) | [English](../../../en/technical/reference/golem-resources.md)

GOLEMは、ロジックブロックをグリッドに配置する編集画面です。
画面用の画像、ブロック名と説明、画面を組み立てるためのレコードを持っています。
両バージョンのYAMLでは、これらを1つの`golem_data` databinにまとめています。
ビルドでは元のバイト列をそのままリンクし、別の抽出ツールで中身を見られるようにします。

```sh
make splat
make extract-golem

make splat VERSION=jp
make extract-golem VERSION=jp
```

出力先は`assets/exports/<version>/overlays/golem/`です。
`GOLEM_OUTPUT=/path/to/new-folder`で別の場所を指定できます。
既存のフォルダは上書きしません。すべて読み終えてから一時フォルダに書き込み、
完了した時点で出力先へ移動します。書き込みに失敗した場合は一時フォルダを削除します。

## 出力されるもの

| パス | 内容 |
| --- | --- |
| `byte-map.yaml` | TIM末尾の繰り返しワードや編集状態を含む、blob内の全範囲 |
| `image/image.tim` | 元の256 x 256、4ビットのテクスチャと16個のパレット |
| `image/image.yaml` | 格納時の画像配置、パレット値、グリフのプレビュー情報 |
| `image/palette_00.png`から`palette_0F.png` | 各パレットで表示したテクスチャ全体 |
| `image/glyphs/` | 79枚のグリフプレビュー。それぞれを16パレットすべてで表示 |
| `text/archive.bin` | 元のテキストアーカイブ全体 |
| `text/archive.yaml` | 2つのセクションのオフセット |
| `text/names.yaml` | 58件のロジックブロック名。番号と元のコード付き |
| `text/descriptions.yaml` | 名前と同じ番号で参照する58件の説明 |
| `tables/glyph_metrics.yaml` | 空の3件も含む、全82件のグリフレコード |
| `tables/panels.yaml` | デコードしたフィールドと元のバイト列を持つ、全154件のパネルレコード |

テクスチャ、グリフ情報、パネルレコードはUSとJPで同一です。
異なるのはテキストアーカイブですが、両版とも名前と説明はそれぞれ58件あります。
空のエントリも含め、番号とセクション先頭からの文字列オフセットをそのまま残すので、
ロジックブロックのIDとの対応を維持できます。

日本版のテキストは、同じバージョンのCLOADの文字表でデコードします。
`make splat VERSION=jp`でそのblobも抽出され、文字表の出所は`byte-map.yaml`に
記録されます。北米版の辞書コードや制御コードは、FIELDやCLOADの出力と同じく
波括弧で表示します。元のアーカイブにはオフセット表、終端、パディングをすべて残します。

## 画像の見方

GOLEMのグリフレコードには、パレットの指定がありません。
描画時に呼び出し側が指定するので、抽出時に1つだけ選ぶとほかの使い方が見えなくなります。
そこで、各グリフのPNGにはパレット0から15を4列4行で並べます。
順番は左から右、上から下です。16 x 16のグリフなら、プレビューは64 x 64になります。
番号0、20、53はサイズがゼロです。YAMLには残しますが、空のPNGは作りません。

プレビューは元の色を表示し、値ゼロを透明、それ以外を不透明にします。
実行時の色調変更、半透明合成、下に敷くタイルは再現しません。
元のTIMはSTPビットも含めてパレット値を保ちます。
格納された座標は画像が(0, 0)、16 x 16のパレット領域が(0, 480)です。
GOLEMは画像を(320, 0)に転送し、256色のパレットを1行に並べて(0, 498)へ転送します。

完成したロジックブロックのアイコンには、FIELDが持つ形状情報とセーブデータの値も
必要です。形状情報はこのblobには入っていません。
[FIELDの抽出ツール](field-resources.md)が`tables/golem_shapes.yaml`として出力します。

## パネルレコードと実行時の状態

パネルレコードは1件20バイトです。詰め込まれたワードから、テクスチャの領域、
パレット、合成モード、表示条件、点滅タイマを読み取ります。
出力では、元画像のセルサイズと画面上の矩形を別々に表示します。
描画処理はそのセルを繰り返して矩形を埋め、格納されたX座標に8ピクセル加えます。
セルの高さはワード境界をまたいで格納されているため、YAMLでは両方を合わせた値を
表示します。元のワードと予約フィールドも残します。
表示条件の名前は`golem.c`の列挙型から取得します。

データblobはUSが39,440バイト、JPが39,000バイトです。
両版とも、編集用の変数やバッファとしてゼロで埋められた292バイトを含みます。
この領域はバイトマップに記録し、別のファイルにはしません。
全バイトを扱えているため、どちらの版も`unknown/`フォルダは不要です。
意味の分からない非ゼロのデータが残った場合は、変更せずにそこへ保存します。

[`golem.py`](../../../../tools/overlays/golem.py)も、ほかの抽出ツールと同じく、
読み取り処理、`Part`、書き込み処理を分けています。
コードより前にあるrodataは、これまでのC単位に残します。
抽出結果を編集しても、ビルドがリンクするデータは変わりません。
