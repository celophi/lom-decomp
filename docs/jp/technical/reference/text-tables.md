# テキストテーブル

[日本語ドキュメント](../../README.md) | [English](../../../en/technical/reference/text-tables.md) | [セーブファイルの形式](save-file.md) | [圧縮ツール（英語）](../../../../tools/compression/README.md)

『聖剣伝説 LEGEND OF MANA』のメニュー画面に出てくる言葉の多くは、コードの中にはありません。
各オーバーレイの中にある小さな文字列テーブルに入っていて、コードはテキストそのものではなく「26番の文字列」のように番号で指定します。
画面を翻訳したい、誤字を直したい、メッセージの内容を知りたい、という場合は、このテーブルを見てください。

このページでは、テーブルの構成と、北米版のテキストの文字コードを説明します。
例には、2Pの主人公の画面（ADDHERO）を使います。最初に全部を解読できたテーブルだからです。

## テーブルの探し方

ADDHEROのテキストを読むだけなら、近道があります。
`make splat` の後に `make extract-addhero` を実行すると、すべてのメッセージと場所の名前がYAMLファイルに、パーティーのアイコンがPNGに書き出されます。
`make extract-carda` ではセーブ画面のデータを同じように書き出し、アイテム名やメモリーカード用のアイコンも含まれます。
日本版のデータには、どちらのコマンドにも `VERSION=jp` を付けます。
詳しくは[オーバーレイのリソース抽出ツール（英語）](../../../../tools/data/overlays/README.md)を参照してください。
この節の残りは、バイト列を直接扱う場合の説明です。

オーバーレイは、ディスクに圧縮された状態で入っています。
ディスク上のファイルの先頭1バイトは形式を示すタグで、その直後から圧縮データが始まります。
このプロジェクトのデコーダーで展開できます。

```sh
size=$(stat -c %s disc/jp/BIN/ADDHERO.BIN)
python3 tools/compression/decompress.py disc/jp/BIN/ADDHERO.BIN 1 $((size - 1)) addhero.bin
```

北米版の場合は、`disc/us/BIN/` から展開してください。

展開したファイルは、メモリー上にあるオーバーレイそのものです。
`0x80140000` に読み込むオーバーレイなら、ファイルの先頭がそのアドレスに当たります。
そのため、`0x80146F9C` にあるテーブルは、展開したファイルのオフセット `0x6F9C` から始まります。

| テーブル | 版 | アドレス | 展開したファイル内のオフセット | 件数 |
|---|---|---|---|---|
| ADDHEROのメッセージ | 日本版 | `0x80146F9C` | ADDHERO.BINの `0x6F9C` | 90 |
| ADDHEROのメッセージ | 北米版 | `0x80146FA4` | ADDHERO.BINの `0x6FA4` | 91 |
| ADDHEROの場所の名前 | 日本版 | `0x801475B0` | ADDHERO.BINの `0x75B0` | 63 |
| ADDHEROの場所の名前 | 北米版 | `0x80147470` | ADDHERO.BINの `0x7470` | 63 |
| FIELDのメニューの文字列 | 日本版 | `0x800EBF90` | FIELD.BINの `0x9C1B8` | 37 |
| FIELDのメニューの文字列 | 北米版 | `0x800EC3C4` | FIELD.BINの `0x9C754` | 37 |

FIELDは、日本版では `0x8004FDD8`、北米版では `0x8004FC70` に読み込まれます。
FIELDのオフセットがアドレスよりその分だけ小さいのはそのためです。

場所の名前は、セーブ画面で各セーブの横に表示されるものです。
セーブのBGMのトラックを使って選ばれます（[セーブファイルの形式](save-file.md)を参照）。

## テーブルの構成

テーブルは、16ビットのオフセットを並べたリストと、その後ろの文字列でできています。

```text
文字列0のオフセット     （2バイト）
文字列1のオフセット     （2バイト）
...
文字列N-1のオフセット   （2バイト）
文字列0、続けて0のバイト
文字列1、続けて0のバイト
...
```

オフセットは、ファイルの先頭ではなくテーブルの先頭から数えます。
件数はどこにも書かれていません。
最初のオフセットは最後のオフセットのすぐ後ろを指しているので、それを2で割ると文字列の数がわかります。
北米版のADDHEROのメッセージテーブルでは、最初のオフセットが `0xB6` なので、文字列は91個です。

26番の文字列を読むには、テーブルの先頭 + 26 × 2 にある16ビットの値を取り出し、それをテーブルの先頭に足して、0のバイトまで読みます。

空の文字列を指しているオフセットもあります。
ADDHEROには、そういう使われていないエントリーがいくつかあります。
また、北米版では空でも、日本版にはテキストが入っているメッセージが1つあります。

## 北米版のテキストの文字コード

北米版の文字列はほとんどがただのASCIIなので、バイナリエディターでそのまま読めることがよくあります。
面白いのは `0x20` より小さいバイトです。
FIELDのテキスト描画処理は、これらを次のように扱います。

| バイト | 意味 |
|---|---|
| `0x00` | 文字列の終わり |
| `0x01`〜`0x13` | 書式の命令。改行、ボタン待ち、消去、選択肢、連続したスペース、ウェイト、色の変更、字下げ |
| `0x14`〜`0x18`、`0x1A`〜`0x1E` | よく使う単語の一部。辞書に1回だけ格納されている |
| `0x19` + 1バイト | 2バイト文字 |
| `0x1F` + 1バイト | 1バイトで表せない分の辞書のエントリー |
| `0x20`〜`0x7F` | ASCII |
| `0x80` 以上 | 幅の決まった特殊文字。「はい」「いいえ」の選択肢に出る記号など |

辞書は、簡単な圧縮の工夫です。
「in」や「is 」のような語はゲームのテキストのあちこちに出てくるので、それぞれ1バイトで表します。
たとえば、バイト `0x16` は「in」を表します。`Load`、`0x16`、`g` の並びは「Loading」と読めます。
バイナリエディターで見た文字列が、ところどころ文字の代わりに妙なバイトが入った英語に見えるのはそのためです。

この辞書は北米版にしかありません。
ゲームはこれをRAMに読み込みますが、ディスクのどこから読んでいるのかはまだ調べていません。
バイトがこの表のとおりに動かない場合は、[field_text.c](../../../../src/overlays/field/ui/field_text.c) の描画処理が正です。

### 日本版のテキスト

日本版もテーブルの構成は同じですが、文字はASCIIではありません。
`0x20` 以上の1バイトが1文字で、ほとんどがかなです。
`0x19`〜`0x1F` のバイトと次の1バイトの組み合わせは漢字です。最初のバイトで256文字ずつの7つのページのどれかを選び、2つ目のバイトで文字を選びます。

メモリーカードのタイトルを書くオーバーレイは、名前をシフトJISに変換するために、文字の一覧表を丸ごと持っています。
ADDHEROにもその写しがあり、`make extract-addhero VERSION=jp` はそれを使って日本語のメッセージを読める文字で書き出します。
一覧表そのものは `tables/text_conversion.yaml` に出力されます。

### メモリーカードのタイトルは別物

メモリーカード管理画面に出るセーブのタイトルは、ゲーム内のテキストではありません。
カードのヘッダーに、PlayStationのBIOSが使う標準の日本語の文字コードであるシフトJISで保存されています。
ゲームはセーブするときに、プレイ時間と主人公の名前からタイトルを作り、シフトJISに変換します。
2Pの主人公の画面は、別のゲームのセーブを一覧に出すとき、このタイトルをBIOSのフォントで描画します。
タイトルの格納場所は[セーブファイルの形式](save-file.md#メモリーカードのヘッダー)を参照してください。

## テーブルの編集

長さを変えずに文字列を変えるのは簡単です。
バイトを上書きして、最後の0を残しておけば済みます。

長くする場合は注意が必要です。

- **後ろの文字列を動かす必要があります。**
  26番の文字列が長くなると、その後ろの文字列はすべてずれるので、26番より後ろのオフセットをすべて直す必要があります。
- **テーブルは元の大きさを超えられません。**
  テーブルは、オーバーレイのほかのデータと隙間なく並んでいます。
  最後の文字列の後ろのバイトは別のデータなので、テーブルを移動しない限り、全体が元の大きさに収まる必要があります。
- **コードは文字列を番号で探します。**
  テキストの中身は見ていないので、オフセットの順番は変えられません。
  使わない文字列があっても、エントリーの数は変えないでください。
- **オーバーレイを圧縮し直す必要があります。**
  ディスク上のファイルは圧縮されているので、編集したオーバーレイは[圧縮ツール（英語）](../../../../tools/compression/README.md)でもう一度圧縮しないと、ゲームが読み込めません。

短くするほうが安全です。
0のバイトで埋めて、オフセットはそのままにしてください。

## コードでの使われ方

ソースでは、コードが名前で使う文字列ごとにシンボルを付けています。
たとえば、メモリーカードがないというメッセージは `g_addhero_text_no_card` です。
ADDHEROの名前と、各メッセージの用途は [addhero_internal.h](../../../../src/overlays/addhero/internal/addhero_internal.h) にまとめています。
メッセージを探すときは、テーブルを順に見るより、オーバーレイのソースをシンボル名で検索するほうがたいてい早く見つかります。
