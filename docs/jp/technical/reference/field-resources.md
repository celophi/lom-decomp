# FIELDのリソース

[日本語一覧](../../README.md) | [抽出ツール](../../../../tools/data/overlays/README.md) | [English](../../../en/technical/reference/field-resources.md)

FIELDには、シーンを切り替えても使い続ける共通の画像やテーブルが入っています。
両バージョンのYAMLでは、このデータを1つの`field_data` databinにまとめました。
ビルドは元のバイト列をそのままリンクし、別の抽出ツールで中身を見られるようにします。

```sh
make splat
make extract-field

make splat VERSION=jp
make extract-field VERSION=jp
```

出力先は`assets/exports/<version>/overlays/field/`です。
`FIELD_OUTPUT=/path/to/new-folder`で別の場所を指定できます。
既存のフォルダは上書きしません。すべての読み取りを終えてから書き込みを始め、
書き込みに失敗した場合は一時フォルダを削除します。

日本版のテキストは、CLOADの文字表を使って日本語に変換します。
`make splat VERSION=jp`で、そのblobも抽出されます。
文字表の出所とアドレスは`byte-map.yaml`に記録します。
FIELD自身にこの変換表が入っているわけではありません。

## 出力されるもの

| フォルダ | 内容 |
| --- | --- |
| `images/common/` | 元の512 x 256 TIM、格納時の配置、64パレット分のプレビュー |
| `images/transition/` | 2枚のフェード用タイルを含む32 x 64の16ビットTIMとPNG |
| `images/menu_frame/` | 64 x 32のメニュー枠画像、2つのパレットとプレビュー |
| `palettes/` | ゴーレムやポートレートのパレット、オフセットヘッダ、色見本 |
| `text/` | UI、必殺技、コマンド、アイテム、曜日のテキストと、メモリーカードのファイル名や認識対象の製品コード |
| `animations/` | 内蔵アニメーションの索引と202件の定義、元のリソース |
| `actions/` | 4つのアクション記述子テーブルと元のバンク |
| `tables/` | HUDの色、入力やアニメーションの対応表、習得条件、ディスパッチテーブル、ウィンドウ矩形、ゴーレムの形状など |
| `unknown/` | まだ形式が分からない隙間のバイト列。RAMアドレスをファイル名にして保存 |

共通テクスチャのPNGは、画像全体に1つのパレットを適用したものです。
ゲームはスプライトごとにパレットを選ぶので、1枚のプレビューですべてが実行時と
同じ色になるわけではありません。元のTIMにはVRAM座標とパレットの全ビットを残します。
FIELDが実際に画像を転送する位置は(384, 0)で、TIMに格納された座標とは異なります。
プレビューではパレット値ゼロを透明にし、それ以外は不透明に表示します。

アニメーションのYAMLには索引と定義を出力します。パーツ、カーブ、フレームの
データは`animations/resource.bin`に元の位置のまま残します。
アニメーションの再生機能はありません。アクションの出力も共通のフィールドを
デコードし、ハンドラによって意味が変わるパラメータは元のワード値を保持します。

## テキストテーブル

| ファイル | 件数 |
| --- | ---: |
| `ui.yaml` | 37 |
| `techniques.yaml` | 264 |
| `commands.yaml` | 256 |
| `items.yaml` | 256 |
| `item_names.yaml` | 256 |
| `weekdays.yaml` | 6 |

件数は両バージョンで同じです。同じ文字列を指すオフセットも別のエントリとして残し、
コードが使う番号を維持します。北米版の2つのアイテム名テーブルには、
`MenosBronze`と`Menos Bronze`のように、詰めた表記と空白を入れた表記があります。
日本版は同じテーブルのコピーです。すべての文字列に元のバイト列を付けます。
北米版の辞書コードや制御コードは、ほかのオーバーレイと同じく波括弧で表示します。

## バイトマップに残すもの

| バージョン | データblob | ゼロで埋められた実行時領域 | 未解釈の隙間 |
| --- | ---: | ---: | ---: |
| US | 360,596バイト | 204,144バイト | 5ファイル、計188バイト |
| JP | 347,984バイト | 191,824バイト | 5ファイル、計189バイト |

バイトマップは、パディングやリソース末尾の繰り返しワードも含めて全バイトを扱います。
ゼロで埋められた実行時領域は、別のファイルにはしません。
隙間の集計には、アニメーショントラックなど、既知のリソース内部でまだデコード
していないデータは含みません。意味が分からないバイト列は、推測で形式を決めずに
そのまま保存します。元の配列長が確定していない小さなテーブルでは、格納された
パディングも値の列に残します。関数ポインタには、判明していればシンボル名も付けます。
リソース番号とポインタが混在するテーブルでも元の値を維持します。

読み取りと出力は[`field.py`](../../../../tools/data/overlays/field.py)、小さなテーブルの
形式は[`field_tables.py`](../../../../tools/data/overlays/field_tables.py)にあります。
コードより前にあるジャンプテーブルなどのrodataは、これまでの所有元に残します。
抽出結果を編集しても、ビルドがリンクするデータは変わりません。

シーン固有の素材はここには含まれません。`ANA/INFO_*/*.IMG`の中身を見るには、
[シーン抽出ツール](scene-extractor.md)を使います。
