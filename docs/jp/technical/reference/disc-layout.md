# ディスクの構成

[日本語ドキュメント](../../README.md) | [English](../../../en/technical/reference/disc-layout.md)

ディスク上のファイルに何が入っているのかと、実行中のゲームがそのデータをどう指定するのかを説明します。
現時点では、北米版（NTSC-U）の `SLUS-01013` を対象にしています。

## ディスクの基本情報

| 項目 | 値 |
|---|---|
| 製品コード | SLUS-01013（北米版） |
| 起動設定 | `SYSTEM.CNF` |
| 起動する実行ファイル | `cdrom:\SLUS_010.13;1` |
| メイン実行ファイルのサイズ | 約194 KB（`SLUS_010.13`） |
| 抽出したファイルの合計 | 約563 MB、5036ファイル |

`SYSTEM.CNF` の内容は次のとおりです。

```
BOOT = cdrom:\SLUS_010.13;1
TCB = 4
EVENT = 16
STACK = 801FFFF0
```

`SLUS_010.13` はメイン実行ファイルです。Psy-Qなど、各処理で共通に使うライブラリのデータも含まれています。
ゲームモードに応じて、`BIN/` のオーバーレイを決まったメモリアドレスへ読み込む処理を管理しています。

## 実行中のデータの指定方法

後で出てくる `ANA`、`MAP`、`WM` などのISOディレクトリ構造は、制作時のファイルの整理方法です。
実行中のゲームは、パスを指定してファイルを開きません。起動設定の行を除くと、コード内に `cdrom:\...` というパス文字列はありません。
代わりに、整数のリソース番号をディスク上の位置（LBA）とバイト数に対応付ける**リソーステーブル**を使って、すべての読み込みを行います。

この対応表は `SKCDPOSE.DAT` に入っています。名前は「skip CD position」のような意味かもしれませんが、確定していません。
データは `CdResourceEntry` を要素とする配列です。

- `CdResourceEntry` は `{ CdlLOCRaw location; s32 data_size; }` で、1件8バイトです。
  4バイトのディスク位置（BCD形式の分・秒・フレームとモード1バイト）に、リトルエンディアンのバイト数が続きます。
  使用されているエントリーのモードはすべて `0xFF`、空きスロットは `0x00` です。[src/main/cdrom.c](../../../../src/main/cdrom.c)を参照してください。
- テーブルはRAM上の `CD_RESOURCE_ENTRIES = 0x801ED998` に置かれます。
- `CdlLOC` の位置情報は、次の式でLBAに変換できます。
  `(((minute * 60) + second) * 75) + sector - 150 = LBA`
- ゲーム側は `cdrom_queue_read(resource_index, dst)` を呼び出します。
  CD-ROMサブシステムが、リソース番号、`CdResourceEntry`、LBAの順に参照先を解決します。
  詳しくは[CD-ROMサブシステム（英語）](../../../en/technical/architecture/cdrom.md)を参照してください。

名前の付いたリソース番号は [include/main/cd_resources.h](../../../../include/main/cd_resources.h) にあります。
先頭付近の対応は次のとおりです。すべて実際のテーブルを解析して確認しています。

| 番号 | ファイル | 番号 | ファイル |
|--:|---|--:|---|
| 0 | SYSTEM.CNF | 12 | CARDA.BIN |
| 1 | SLUS_010.13 | 13 | GOSUB.BIN |
| 2 | FIELD.BIN | 14 | WSEL.BIN |
| 3 | WMAP.BIN | 15 | CHECKPS.BIN |
| 4 | TITLE.BIN | 16 | CLOAD.BIN |
| 5 | GNAME.BIN | 17 | NIKI.BIN |
| 6 | MENU.BIN | 18 | ADDHERO.BIN |
| 7 | SHOP.BIN | 19 | 空き・予約スロット |
| 8 | ZUKAN.BIN | 20 | 空き・予約スロット |
| 9 | GOLEM.BIN | 21 | SOUND/EFFECT.SET |
| 10 | GOVER.BIN | 22 | SOUND/WAVE0001.DAT（ADPCMサンプルバンク） |
| 11 | MOVIE.BIN | 23 | SOUND/MSC_DATA.DAT |
| | | 24以降 | MUSIC002.SET, MUSIC003.SET, ... |

ディレクトリ内のファイル名は、人がデータを識別するための名前です。
製品版のゲームは、`SKCDPOSE.DAT` にあらかじめ記録されたLBAを使って各データを読み込みます。

## ディスクの確認

`MAP/FDATA/SK.DAT`（21バイト）は、起動時に照合するディスク識別文字列です。
「SK」はおそらく「聖剣」を指していると思われます。内容は次のとおりです。

```
90 b9 8c 95 20 53 51 55 41 52 45 20 53 4f 46 54 28 55 53 29 00
                S  Q  U  A  R  E     S  O  F  T  (  U  S  )
```

先頭の4バイト `90 b9 8c 95` はShift-JISの「聖剣」で、その後に「 SQUARE SOFT(US)」が続きます。
`cdrom_verify_disc()` が `CdGetSector` でこのセクターを読み、`g_disc_validation_id[21]` と比較します。
一致しなければディスクを受け付けず、`CD_INIT_STATE_ERROR_PAUSE` に移ります。

### オーバーレイ（`BIN`）

17個の `.BIN` ファイルが、ゲームモード別のオーバーレイです。
それぞれ [src/overlays/](../../../../src/overlays/) 内のディレクトリに対応し、コードやデータの前に4バイトのモジュールIDを持ちます。
ロードアドレスとIDは[オーバーレイのIDプレフィックス](overlay-id-prefix.md)にまとめています。
日本語の名前を略したものもあるので、名前から用途がわかるものもあります。

| BIN | src/overlays | 用途 |

| `GOLEM.BIN` | `golem` | ゴーレム工房のミニゲーム |
| `GOSUB.BIN` | `gosub` | 共通サブルーチン用オーバーレイ |
| `GOVER.BIN` | `gover` | ゲームオーバー |
| `MENU.BIN` | `menu` | メインメニュー |
| `MOVIE.BIN` | `movie` | ムービー再生ドライバー |
| `NIKI.BIN` | `niki` | 日記 |
| `SHOP.BIN` | `shop` | ショップ |
| `TITLE.BIN` | `title` | タイトル画面 |

| `ZUKAN.BIN` | `zukan` | 図鑑 |

### フィールドマップ（`MAP`）

`MAP0` から `MAP4` までの5つのディレクトリと、`FDATA` に分かれています。
マップは、ディスク上では次の2つの形式で格納されています。

- `.MPD` - 非圧縮のフィールドマップ。識別文字列は `"SKmapDat"` です。
  非圧縮のまま収録されているのは少数で、`MAP0` のテスト用・戦闘用マップなどです。
- `.PRS` - `.MPD` をLZ圧縮したもの。ヘッダーは `01 0e` で始まり、その後にペイロードの先頭リテラルである「SKmapDat」が見えます。
  製品版のマップの大部分はこちらです。

`MAP/FDATA` には、共通データが3つあります。
圧縮フォントの `FONT.PRS`、メニューウィンドウ画像の `M_WIN.PRS`、先ほどのディスク識別文字列 `SK.DAT` です。

**マップの命名規則**は `PREFIX_AREA` です。

- 接頭辞は場所のコードです。`DRL`、`SHP`（船）、`TWR`（塔）、`JGL`（ジャングル）、`SEA`、
  `MNT`（山）、`SNW`（雪）、`RUI`（遺跡）、`MIN`（鉱山）、`LAK`（湖）、`PRT`（港）、`CV1`（洞窟）など、約30種類あります。
- 後半は区画の種類です。`FD`（フィールド）、`RM`（部屋）、`DN`（ダンジョン）、`BSS`（ボス）、
  `STR`（通り）、`DCK`（甲板）、`BCH`（浜辺）、`ENT`（入口）、`1F` / `2F` / `3F`（階）、
  `FD00`、`FD01` のような連番などがあります。

### ムービー（`MOVIE`）

- `.STR` - 標準的なPSXのMDEC映像ストリーム。XA音声とセクター単位で交互に配置されます。
  オープニングの `OPEN.STR`（43M）、`POST.STR`、スタッフロールの `STAFF.STR`（110M、ディスク内で最大の単一ファイル）、
  ボスやイベントごとの映像などがあります。
- `.DAT` - 一部の映像に付随するストリーミング音声データです。
  `GIRA.DAT` / `GIRA.STR`、`KAJU.DAT` / `KAJU.STR` の組み合わせや、ボス登場時の音声 `*_BSS*.DAT` などがあります。
  内容はADPCM系の生のサンプルデータで、MDEC映像ではありません。

`MOVIE.BIN` の `movie` オーバーレイが、[cdrom.c](../../../../src/main/cdrom.c) のストリーミング処理を通して再生します。

### オブジェクト画像（`ANA`）

拡張子ごとの用途は次のとおりです。

- `.IMG` - Square独自のリソースで、内部構成は複数あります。
  `ANA/INFO_*` は、アクター、スクリプト、テキスト、形状データ、テクスチャをまとめたシーンコンテナーです。
  [シーン抽出ツール](scene-extractor.md)を参照してください。
  ほかにはスプライトやアニメーションのバンクもあります。オフセットテーブルはよく使われますが、共通の識別値があるわけではありません。
- `.DAT` - `.IMG` バンクに付随する汎用データです。`.IMG` に画像、`.DAT` に制御データ、という組み合わせがよく見られます。
- `.STV` - **戦闘エフェクトのアニメーションスクリプト**です。すべて `EFFECT/*` 配下の `BAT_EF*`、`RENEF*` などにあります。
  同じディレクトリには、派生形式の `.SV` が7個、エフェクトセットのインデックスである `.ST` が1個（`JYO_SET.ST`）あります。
- `.TIM` - 通常のPSXテクスチャです。
- 数字が拡張子になっているファイル - **TIM画像の連番**で、拡張子は形式ではなくフレーム番号です。
  `ANA/ENDMES/SC_END.1..84`（エンディングのメッセージ画像）と `ANA/EVTITLE/TITLEF.1..99`（イベント・エリアのタイトル画像）は、
  どちらもTIMの識別値で始まります。順序のあるTIMフレーム群として扱います。
- 拡張子のない `ANA/B_NPCOBJ/BTLNPC0B` - 先頭にTIMヘッダーを持つ戦闘用NPCオブジェクト画像で、拡張子だけがありません。

サブディレクトリは用途ごとに分かれています。
`ADD_OBJ`、`EFFECT`（戦闘エフェクト）、`B_NPCOBJ` / `F_NPCOBJ`（戦闘用・フィールド用NPC）、
`B_PETOBJ` / `F_PETOBJ`（ペット）、`BTL_OBJ`（戦闘）、`RINGDATA`（リングコマンドUI）、
`ZUKAN_P`（図鑑の画像）、`INFO_*`（地域別情報）、`MAPINFO`、`ENDMES`（エンディング）、`EVTITLE`（タイトル画像）などです。

### ワールドマップ（`WM`）

ランドメイクのワールドマップ処理（`WMAP.BIN`）で使うデータです。26個のサブディレクトリがあります。

- `.DAT` - 汎用の配置・制御データです。
- `.PIM` - パック・圧縮されたワールドマップのタイル画像です。
  ヘッダーは `01 00 10 f0` で、`.PRS` / `.PAT` と同系統の圧縮形式です。`WMAP` と `WMTIM/WMAPT*` にあります。
- `.TIM` - テクスチャです。
- `.BTP` - ワールドマップのエフェクト画像です。`.IMG` と同様にオフセットテーブルを使います。
  `WEFF*` / `WCV1` / `WKAJU` / `WPRT` / `WRUI` のエフェクト用ディレクトリにあります。
- `.PAT` - `WMAP` に1個あります。圧縮されたワールドマップのパターン・配置データです。
  非圧縮データ内の位置は、拡張子のない `WM/TEST/LANDDATA` のオフセットテーブルで指定されます。
  両者には `68 4a`、`54 6b` など、同じオフセット値が見られます。
- `.CLT` - `WEFF` に1個あります。TIM形式のCLUT（パレット）で、ヘッダーはTIMの識別値です。「CLT」はCLUTを指します。

サブディレクトリは地域や機能ごとに分かれています。
`WLAND`、`WSEA`、`WSNW`、`WMNT`、`WTWR`、`WPRT`、`WRUI`、`WMAP`、`WMDATA`、
`WEFF*`（エフェクト）、`WLOAD`、`WHLP`（ヘルプ）、`WKAJU`、`MOGU`、`SND` などです。

### 音声

Squareの**AKAO**サウンドエンジンを使っています。各 `.SET` のオフセット `0x0C` に、識別文字列 `"AKAO"` が見えます。
AKAO関連のデータはいろいろな場所にあります。調査では `FFVII` のデコンパイルWikiがかなり参考になりました。
シーケンスは3つのグループに分かれていて、さらに効果音バンクがあります。

| ディレクトリ | 拡張子 | 用途 |
|---|---|---|
| `SOUND` | `.SET` | 共通の音楽と `EFFECT.SET`。`MSC_DATA.DAT` がインデックス |
| `SND_SOTO` | `.SET` | 屋外・フィールド用の音楽（`MUSICS01` から `MUSIC026`） |
| `SND_HERO` | `.EFF` | 武器・アクションの効果音（`KEN`、`AXE`、`YARI`、`ROD`、`HAMMER` など） |
| `SND_MON` | `.EFF` | モンスターの効果音。敵・ボスごとのバンク |

`.EFF` の先頭には、バンク内の個々のサンプルを指す32ビットのオフセットテーブルがあります。
`MUSIC*.SET` の名前はBGMの曲番号を表します。

### 埋め合わせ用のデータ

- `NULL/NULL3.DAT`（27M）と `FUKU/TEST.TIM` は、ゲームプレイ用のデータではありません。
  `NULL3.DAT` は配置やシーク時間を調整するための埋め合わせで、生成されるLBA値を調整する目的だった可能性が高いと考えています。
  `TEST.TIM` はテスト用テクスチャの名残です。

## ファイル形式の早見表

| 拡張子 | 識別値（先頭のバイト列） | 形式 |
|---|---|---|
| `.MPD` | `53 4b 6d 61 70 44 61 74` "SKmapDat" | 非圧縮フィールドマップ |
| `.PRS` | `01 0e ...` | LZ圧縮された `.MPD` またはリソース |
| `.STR` | PSXのセクター同期ヘッダー | MDEC映像とXA音声のストリーム |
| `.SET` | `... "AKAO" @0x0C` | AKAOの音楽・効果音シーケンス |
| `.EFF` | オフセットテーブル | AKAOサンプルバンク（効果音） |
| `.TIM` | `10 00 00 00` | 標準のPSX TIMテクスチャ |
| `.CLT` | `10 00 00 00` | TIM形式のCLUT（パレット） |
| `.IMG` | オフセットテーブル（構成は形式ごとに異なる） | Squareのシーンコンテナー、スプライト・アニメーションリソース |
| `.STV` / `.SV` | `xx xx 01 00 ...` | 戦闘エフェクトのアニメーションスクリプト（`ANA/EFFECT`） |
| `.BTP` | オフセットテーブル | ワールドマップのエフェクト画像 |
| `.PIM` | `01 00 10 f0 ...` | 圧縮されたワールドマップのタイル画像 |
| `.PAT` | `01 00 a0 f0 ...` | 圧縮されたワールドマップのパターン・配置データ |
| `.BIN` | MIPSコードと4バイトのID | 読み込んで実行するゲームモード別オーバーレイ |
| `.DAT` | 形式による | 付随データ、ストリーミング音声、テーブルなどの汎用コンテナー |
| `SC_END.N` / `TITLEF.N` | `10 00 00 00` | TIM画像の連番（エンディング・タイトル画像） |
| `SK.DAT` | `90 b9 8c 95`（SJIS） | ディスク識別文字列 |
| `SKCDPOSE.DAT` | バイナリテーブル | 起動時に読み込むLBA・サイズのリソーステーブル |
