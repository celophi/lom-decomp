# TITLEのリソース

[日本語一覧](../../README.md) | [抽出ツール](../../../../tools/overlays/README.md) | [English](../../../en/technical/reference/title-resources.md)

TITLEは、タイトルメニューと、ニューゲームの後に続くキャラクターと武器の選択画面を
動かしています。データには、メニューの画像、選択画面のテクスチャと配置、
11本の初期武器、ニューゲームの元になるゲーム状態が入っています。
以前のYAMLではこれを多くの型付きセグメントに分けていましたが、
両バージョンとも1つの`title_data` databinにまとめました。ビルドでは元のバイト列を
そのままリンクし、別の抽出ツールで中身を見られるようにします。

```sh
make splat
make extract-title

make splat VERSION=jp
make extract-title VERSION=jp
```

出力先は`assets/exports/<version>/overlays/title/`です。
`TITLE_OUTPUT=/path/to/new-folder`で別の場所を指定できます。
既存のフォルダは上書きしません。すべて読み終えてから一時フォルダに書き込み、
完了した時点で出力先へ移動します。書き込みに失敗した場合は一時フォルダを削除します。

## 出力されるもの

| パス | 内容 |
| --- | --- |
| `byte-map.yaml` | TIM末尾の繰り返しワードやメニューの状態を含む、blob内の全範囲 |
| `title_menu/offsets.yaml` | メニュー用TIM 2枚の個数と、表自身からのオフセット |
| `title_menu/menu_items/` | 256 x 256、4ビットのメニュー文字テクスチャ。`image.tim`とパレットごとのPNG(16枚) |
| `title_menu/backdrop/` | 320 x 240、16ビットのタイトル背景。`image.tim`と`image.png` |
| `title_menu/cursor_blink.yaml` | カーソルの点滅4フレームそれぞれのテクスチャU座標 |
| `save_slot_menu/textures.yaml` | 選択画面のTIM 11枚をVRAMのどこへ転送するか |
| `save_slot_menu/textures/00/`から`10/` | そのTIMと、パレットで表示したプレビュー |
| `save_slot_menu/panel_uvs.yaml`、`sprite_uvs.yaml` | ステージの左右それぞれで使う12個の転送元矩形(ピクセル単位) |
| `save_slot_menu/layout.yaml` | 画面を組み立てる27個のプリミティブと、その初期値 |
| `save_slot_menu/starting_weapons.yaml` | 武器の種類ごとに1件、計11件の武器レコード |
| `game_state/new_game.yaml`、`.bin` | ニューゲーム開始時の状態。デコード結果と元のバイト列 |
| `game_state/alternate.yaml`、`.bin` | ほかのメニュー項目が使う、もう1つの完全な状態 |
| `game_state/hero_default.yaml`、`hero_continue.yaml`、`.bin` | 選択画面がパーティへコピーする2件の主人公レコード |

コードでは選択画面をセーブスロットメニュー(`run_save_slot_menu`)と呼んでいるので、
フォルダ名もそれに合わせています。実際の中身は、文字テクスチャにある
"Select your character."と"Select your weapon."を見るとわかります。

どのYAMLにも、デコードした値の横にリソースのアドレスと元のバイト列を残しています。
抽出結果を編集しても、ビルドがリンクするデータは変わりません。

## 配置

blobは両バージョンとも721,892バイト(`0xB03E4`)で、各リソースのオフセットも
両版で同じです。JPのアドレスはUSのアドレスに`0xC0`を足した値です。

| リソース | オフセット | サイズ | USアドレス | JPアドレス |
| --- | --- | --- | --- | --- |
| メニューTIMのオフセット表 | `0x0` | `0xC` | `0x800522E8` | `0x800523A8` |
| メニュー文字TIM | `0xC` | `0x8220` | `0x800522F4` | `0x800523B4` |
| タイトル背景TIM | `0x822C` | `0x25814` | `0x8005A514` | `0x8005A5D4` |
| カーソル点滅のオフセット | `0x2DA44` | `0x4` | `0x8007FD2C` | `0x8007FDEC` |
| 選択画面TIM 00から10 | `0x2DA48` | `0x79ACC` | `0x8007FD30` | `0x8007FDF0` |
| テクスチャ転送表 | `0xA7514` | `0xB0` | `0x800F97FC` | `0x800F98BC` |
| パネル用UV表 | `0xA75C4` | `0x48` | `0x800F98AC` | `0x800F996C` |
| スプライト用UV表 | `0xA760C` | `0x48` | `0x800F98F4` | `0x800F99B4` |
| 配置表 | `0xA7654` | `0x288` | `0x800F993C` | `0x800F99FC` |
| 初期武器 | `0xA78DC` | `0x2C0` | `0x800F9BC4` | `0x800F9C84` |
| ニューゲームの状態 | `0xA7B9C` | `0x50BC` | `0x800F9E84` | `0x800F9F44` |
| もう1つの状態 | `0xACC58` | `0x3260` | `0x800FEF40` | `0x800FF000` |
| 主人公レコード(default) | `0xAFEB8` | `0x250` | `0x801021A0` | `0x80102260` |
| 主人公レコード(continue) | `0xB0108` | `0x250` | `0x801023F0` | `0x801024B0` |
| メニューの状態 | `0xB0358` | `0x8C` | `0x80102640` | `0x80102700` |

TIMはどれも標準的なPlayStationのTIMファイルです。メニュー文字テクスチャ以外は、
直後に自分の最後のワードのコピーが続きます。この4バイトはバイトマップで別の範囲として
記録しています。最後の140バイトはメニューの実行時変数(終了状態、フェード色、
カーソルやスライドの位置)です。ディスク上ではすべてゼロなので、バイトマップに
記録するだけでファイルにはしません。どちらの版にもパディングや不明な範囲はありません。

## タイトルメニュー

`offsets.yaml`は個数(2)と、表自身のアドレスから数えた2つのオフセットです。
メニュー文字が`0xC`、背景が`0x822C`です。TITLEはこのTIMに格納された座標を使いません。
メニュー文字のピクセルは(320, 0)へ、256色は1行にまとめて(0, 480)へ、
背景は(320, 256)へ転送します。

メニュー文字テクスチャは16ピクセルずつの行が縦に並んだものです。
0行目は著作権表示のヘッダーで、N行目はメニュースロットN - 1の項目です。
New Game、Load Gameの後に、Quick ContinueやEncyclopediaのような、
メニューが有効にしない項目が続きます。7行目にはカーソルの3フレームがあります。
パレット1はヘッダーと選択中の項目、パレット2はほかの項目、パレット0はカーソルに使います。
メニュー開始時に有効になるのは最初の2スロットだけです。
カーソルのUオフセットは`0, 16, 32, 16`を、4フレームに1回ずつ切り替えます。

## キャラクターと武器の選択画面

11枚のテクスチャは、各TIMに格納された座標ではなく`textures.yaml`の位置へ転送されます。
転送時に、各エントリの制御ワードもTIMの内容(ピクセルモード、幅、高さ)から埋めるので、
格納されている制御ワードはゼロです。テクスチャ01は画面の文字で、USとJPで異なります。
残りの10枚は両版で同じです。

`layout.yaml`には27個のプリミティブが並びます。TITLEは各プリミティブを
オーダリングテーブルの先頭へつなぐので、並びは手前から奥の順です。
最初に描かれるのはエントリ26、テクスチャ00の石の壁です。
各エントリには、フラグ(ステージと一緒に動くか、半透明、ブレンドモード)、
プリミティブの種類、テクスチャ、画面上の位置、塗りつぶしタイル用の別の位置、
テクスチャのU/V、サイズがあります。種類は`hidden`、`sprite_strip`
(最大128ピクセルずつスプライトを横に並べる)、`tile`(暗い塗りつぶしのタイル)、
`panel_quad`、`slot_sprite`です。

| エントリ | テクスチャ | 描くもの |
| --- | --- | --- |
| 0、3から8、10から15 | 01 | 案内文、武器の一覧、小さな目印、暗いタイル2枚 |
| 22、23 | 01 | 主人公の足元の暗い楕円 |
| 1 | 08 | 画面上部の320 x 80の帯 |
| 2、9 | 04 | 各武器一覧の横のバー |
| 16、17 | 05 | 武器一覧の後ろの石のパネル |
| 18、19 | 06、07 | 左右どちらかのキャラクターに当たる光 |
| 20、21 | 09、10 | 2人の主人公のポーズ |
| 24、25 | 02、03 | 2人のキャラクターの肖像 |
| 26 | 00 | 2つの肖像の額縁がある壁 |

エントリ0、2から15、18、19は画面の動作中にTITLEが書き換えるので、
ファイルにあるのは初期値です。キャラクター選択で左右を押すとエントリ18と19の
どちらを表示するかが入れ替わり、それが決定時にステージがどちらへスライドするかを
決めます。両版の違いは案内文(エントリ0)のY座標だけで、USが18、JPが16です。

2つのUV表はそれぞれ12個の矩形を持ち、8ピクセル単位で格納されています。
YAMLではピクセル単位に直して表示します。エントリ20は`panel_uvs.yaml`から
ポーズを選びます。ステージが右へスライドするまではエントリ0、その後は
`武器 + 1`番のエントリです。エントリ21は、ステージが左へスライドした後に
`sprite_uvs.yaml`で同じことをします。

初期武器は、どれも[セーブファイル](save-file.md)の持ち物と同じ64バイトの
アイテムレコードです。レコードの番号が武器の種類で、ナイフ(0)から弓(10)まで並びます。
USでは`MenosKnife`から`MenosBow`、JPでは`ブロンズナイフ`のような名前です。
武器を決定すると、TITLEは選んだレコードを主人公の武器スロットへコピーし、
ほかの武器の種類の技マスクをすべて消します。

## ゲーム状態

ニューゲームでは、`new_game.bin`の先頭12,904バイト(`0x3268`)をゲーム状態へコピーし、
フィールドシーンを`0xD`にしてキャラクター選択画面を開きます。
このコピーは12,896バイトのセーブデータ構造より8バイト長く、セーブファイルへ
コピーする長さと同じです。武器を決定すると、まず`hero_default`か`hero_continue`を
パーティのスロット0へコピーします。ステージが右へスライドした後なら`hero_default`、
左へスライドした後なら`hero_continue`です。後者はモードフラグのワードのビット0も立てます。
2件のキャラクター種別は0と1です。

`alternate.bin`はちょうどセーブデータ構造1つ分です。TITLEは、New Game、Load Game、
放置によるタイムアウト以外のメニュー選択でこれを読み込み、そのままフィールド(シーン0)へ
進みます。こちらのコピーも`0x3268`バイトなので、`hero_default`の先頭8バイトまで読みます。
所持金100,000、配置済みの土地32、アイテム種類0から254をそれぞれ50個持った状態から
始まります。JP版には持ち物が41件ありますが、US版の持ち物レコードは名前がすべて空で、
空きレコードの扱いです。

YAMLでは、[saved_game.h](../../../../include/common/saved_game.h)が名前を付けている
フィールドをデコードします。概要、所持金、技、熟練度、識別子、土地、装備を含む
パーティのキャラクター、持ち物、アイテム個数です。メニュースロット、ゴーレム、
ペットなどそれ以外は`.bin`にだけあります。空きのアイテムレコードと使われていない
土地はYAMLに出力しません。

日本版のテキストは、同じバージョンのCLOADの文字表でデコードします。
`make splat VERSION=jp`でそのblobも抽出され、文字表の出所はバイトマップに記録されます。
北米版のテキストはASCIIで表示し、それ以外のコードは波括弧で表示します。
北米版のゲーム状態と主人公レコードには、主人公の名前`{B9}{AF}{B5}`や
武器スロットの剣のように、日本語のコードの名前がまだ残っています。
剣は武器の選択で上書きされ、その次には名前入力画面が続きます。
2バイト文字の2バイト目がゼロでも、それは終端ではなく文字の一部です。

## まだわかっていないこと

- **ニューゲームの状態の残り。** `new_game.bin`の`0x3260`から`0x50BB`は
  セーブデータ構造の外にあり、`load_saved_game_template`もコピーしません。TITLEの中に
  読むコードはありません。アイテムやスロットのレコードに見えますが、
  使っている場所はまだ見つかっていません。
- **もう1つの状態。** そこへ進むメニュースロットをTITLEは有効にしません。
  ほかに有効にする場所も見つかっていません。
- **主人公レコードの名前。** `hero_default`と`hero_continue`はCのシンボル名に
  合わせています。それぞれが画面上のどちらのキャラクターかは、
  実際のゲームではまだ確かめていません。

[`title.py`](../../../../tools/overlays/title.py)も、ほかの抽出ツールと同じく、
読み取り処理、`Part`、書き込み処理を分けています。TIM、オフセット表、数列、
転送表、UV表、配置表の解析には`tools/assets/`のパーサーを使います。
セーブデータのレコードは[`saved_game.py`](../../../../tools/overlays/saved_game.py)が
読み、そのオフセットはテストでCのヘッダーと照合しています。
