# NTSC-J (SLPS-02170) configuration

Splat configuration for the Japanese release. This folder mirrors
[`config/us/`](../us/) and is selected with `make VERSION=jp`.

The current files are a first pass generated by
[`tools/versions/bootstrap_jp_configs.py`](../../tools/versions/bootstrap_jp_configs.py)
from the fully linked US build:

| Path | Contents |
|---|---|
| `SLPS_021.70.yaml` | Splat config for the main executable (`disc/jp/SLPS_021.70`) |
| `overlays/<NAME>.BIN.yaml` | One splat config per overlay in `disc/jp/BIN/` |
| `symbols/*_symbol_addrs.txt` | US function names ported to their JP addresses |
| `relocations/*_reloc_addrs.txt` | JP relocation overrides (none yet) |

Each module is split coarsely into rodata, one `asm` block for all of its code,
and data. The JP progress report counts each `asm` block as unmatched code.
Splitting a block into `c` subsegments (and adding `jp` to
`TU_LAYOUT_VERSIONS` in `mk/version.mk` once JP has its own source routing)
turns it into real translation units. Once the configs are refined by hand,
stop regenerating them.

Load addresses that differ from US: `gp` is `0x8003ED80` (US `0x8003EC14`),
and the FIELD, WMAP, TITLE, WSEL, and CHECKPS overlays load at `0x8004FDD8`
(US `0x8004FC70`).

Every yaml must also set `generate_asm_macros_files: False` (see
`config/us/`), or `make splat` overwrites the project-owned
`include/include_asm.h`.

Every path inside the yamls points at the `jp` trees (`disc/jp/`, `asm/jp/`,
`linker/jp/`, `assets/jp/`, `build/jp/`) and uses `base_path: ../../` (main
executable) or `base_path: ../../../` (overlays).
